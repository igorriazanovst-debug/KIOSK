# words-library — пакет контента виджета «Я знаю много слов» (Тип 2)

**Сейчас здесь ЗАГЛУШКИ, а не поставочный контент.** Иллюстрации — геометрические фигуры с подписью «заглушка». Озвучка есть, но она **синтезированная** (Windows SAPI, голос Microsoft Irina Desktop), сгенерирована скриптами из `tools/`. Этого достаточно, чтобы писать и проверять игровой цикл и слушать игру руками, и недостаточно ни для демонстрации заказчику, ни для приёмки.

**Почему синтез не годится для приёмки.** План реализации относит синтез речи к тому, что НЕ входит в MVP («Синтез речи вместо записанной озвучки»), а ТЗ (строка 58, FR-019) требует «озвученные слова», не уточняя способ. Пригоден ли синтезированный голос для пособия по развитию речи — решает заказчик или методист, а не разработчик. До такого решения синтез здесь — **средство разработки**: он делает игру проверяемой на слух и позволил замерить реальный вес контента (спайк 0.3 плана). Перед поставкой файлы заменяются записью живым голосом; схема, раскладка и имена файлов при этом не меняются.

## Что должно здесь оказаться к приёмке

По ТЗ (строки 58 и 59) требуется **≥ 250 озвученных слов с иллюстрациями** и **≥ 15 тем**. План берёт с запасом: **≥ 270 слов** и **15 тем с уникальными названиями** — у эталона ОС3 запас по словам всего 4, а уникальных названий тем 13 из 15, и то и другое создаёт риск на приёмке.

ТЗ раздел 10 требует обеспечить законность использования всех изображений, аудио, шрифтов. Значит:

- ресурсы ОС3 использовать нельзя ни в каком виде;
- на каждый материал должен быть источник и лицензия — реестр ведётся вместе с пакетом.

## Устройство пакета

`index.json` — манифест, единственный источник правды о составе:

```jsonc
{
  "schemaVersion": 1,
  "audioScheme": { "voices": [], "phrasesPerVoice": 0, "neutral": false },
  "themes": [{ "id": "digits", "title": "Цифры", "wordIds": ["0000", "…"] }],
  "words":  [{ "id": "0000", "name": "Один", "themeId": "digits", "level": 0 }]
}
```

**Идентификатор слова — четыре цифры: две первые это номер темы, две последние — номер слова внутри темы.** Он же имя файла иллюстрации, он же имя папки озвучки, поэтому путь любого ресурса выводится из идентификатора одной функцией (`packages/shared/src/words/model/resources.ts`).

```
assets/img/words/<id>.svg               иллюстрация слова
assets/img/themes/<themeId>.svg         обложка темы
assets/media/words/<id>/neutral.mp3     нейтральная запись слова
assets/media/words/<id>/<voice>/<n>.mp3 фразовый вариант
assets/media/themes/<themeId>/<voice>.mp3
assets/media/scenes-final/<themeId>.mp3
```

### `audioScheme` — главная развилка бюджета

Схема задаёт, сколько записей полагается каждому слову, и проверка комплектности сверяется именно с ней. Пустой `voices` означает «озвучка ещё не записана» — законное промежуточное состояние, при котором спрашиваются только картинки.

| Схема | Записей на слово | Ориентир по весу на 270 слов |
|---|--:|---|
| Как у эталона ОС3: 5 фраз × 2 голоса + нейтральная | 11 | ~200 МБ |
| Сокращённая: 2 фразы × 1 голос + нейтральная | 3 | **замерено: 14,5 МБ** (см. ниже) |
| Только нейтральная | 1 | минимум, повторы за партию надоедают |

**Текущая схема пакета — сокращённая: `{ voices: ["irina"], phrasesPerVoice: 2, neutral: true }`**, то есть 3 файла на слово.

**Замер от 13.09.2026** (синтезированная озвучка, mp3 VBR `-qscale:a 4`, нормализация `loudnorm` к −16 LUFS): средний файл 17,5 КБ; проекция на целевой каталог 270 слов и 15 тем — 840 файлов озвучки, **14,3 МБ звука, 14,5 МБ всего контента**. Это втрое-вчетверо ниже гипотезы плана (40–60 МБ).

Живая запись будет тяжелее — диктор говорит медленнее синтезатора и паузы длиннее, — но порядок тот же. Для сравнения: схема эталона (11 файлов на слово) в том же пересчёте дала бы около 52 МБ против фактических 198 МБ у ОС3. Значит вес их поставки объясняется не числом файлов, а битрейтом и длиной записей — и это рычаг, который у нас есть.

Решение по схеме для поставки — всё ещё за человеком, см. `Яслов_план_реализации.md`.

## Проверка комплектности

Несоответствие манифесту — **ошибка сборки, а не предупреждение**. У эталона ОС3 в поставке не хватало двух mp3, и дефект дожил до продакшена незамеченным, потому что вариант озвучки выбирается случайно из имеющихся.

## Перегенерировать заглушки-иллюстрации

```
node tools/generate-placeholders.mjs
```

Перезаписывает `assets/` и `index.json` целиком. Когда появится настоящий контент, генератор и этот раздел удаляются.

## Перегенерировать озвучку

Пайплайн перенесён из виджета «Матемашка» (Тип 6), где отработал на 2835 файлах: Windows SAPI синтезирует WAV, ffmpeg переводит в mp3. Ни сети, ни облачных сервисов, ни рантайм-зависимостей — в приложение едут готовые mp3.

Нужны собранный `@kiosk/shared` (`cd packages/shared && npm run build`) и `ffmpeg` с `libmp3lame`.

```
# 1. план: какие файлы и с каким текстом. Пути берутся из resources.ts
node tools/plan-narration.mjs --voices irina --phrases 2 --neutral --out plan.json

# 2. синтез и конвертация. Прогон резюмируемый: готовое пропускает
powershell -ExecutionPolicy Bypass -File tools/generate-narration.ps1 \
  -PlanFile plan.json -PackageRoot assets -FfmpegPath <путь к ffmpeg.exe>

# 3. схема в манифест — только если все требуемые файлы на месте
node tools/apply-audio-scheme.mjs --voices irina --phrases 2 --neutral
```

Шаг 3 заодно считает фактический вес пакета и проекцию на целевой каталог.

### Что важно знать

- **Нумерация фразовых вариантов — с нуля** (`irina/0.mp3`, `irina/1.mp3`), как в `wordAudioPaths`. Планировщик берёт пути из того же модуля, что и проверка комплектности, именно чтобы это не разъехалось: файлы с «естественной» нумерацией от единицы лежали бы на диске, а игра молча их не находила бы — отсутствующий файл очередь воспроизведения не роняет. Один раз так и вышло, поймала проверка комплектности.
- **Схема в манифест пишется только при полном наборе файлов.** Манифест, объявивший озвучку, которой нет, — худший исход: `hasAudio` становится `true`, подпись «озвучка не записана» с экрана исчезает, и ребёнок видит молчащую карточку без объяснений.
- **Изменилось название слова — удалите его mp3 вручную** либо перегенерируйте с `-Force`: резюмируемый прогон смотрит только «файл есть / файла нет» и устаревшую запись не заметит.
- **Нормализация громкости включена по умолчанию.** SAPI отдаёт тихий звук (пик около −15 dB), а плеер поверх применяет свою громкость — в группе детей такое не слышно. `loudnorm` поднимает пик примерно до −1,5 dB.
- **Зависшая служба Windows Audio (`AudioSrv`) заставляет SAPI молча отдавать почти пустой WAV** с нулевым кодом возврата. В скрипте от этого стоит порог на размер WAV и три попытки; саму службу лечит только `Restart-Service AudioSrv`. Проверять результат стоит акустически (`ffmpeg -af volumedetect`), а не по наличию файла: тишина даёт около −91 dB.
- **`.ps1` обязан лежать в UTF-8 с BOM**: PowerShell 5.1 читает файл без BOM в системной ANSI-кодировке и ломает кириллицу в строках.
