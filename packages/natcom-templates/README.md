# packages/natcom-templates

Готовые презентации «Конструктора природных сообществ» (Тип 5) — T5-103,
Эпик 11. Вшиты в сборку `player` через `extraResources`, тот же принцип, что
`packages/chrono-templates`: папка данных без `package.json`/кода, читается
`player`'ом на этапе своей сборки/рантайма относительным путём, без symlink.

## Отличие от `chrono-templates`

У Хронолинии шаблоны — это ТОЛЬКО витрина в `editor-web` («как это может
выглядеть»), без сохранения куда-либо (см. `chrono-templates/README.md`).
Здесь иначе: ТЗ (FR-009 «готовые интерактивные презентации», FR-016
«изучение на базе готовых презентаций») требует, чтобы готовая презентация
была РЕАЛЬНО открываема и изучаема в плеере, а не только показана как
картинка. Поэтому каждый файл здесь — полноценный `NatComProject`
(`isDefault: true`), который teacher может открыть на экране «Главная»
(раздел «Готовые презентации» — T5-103); при открытии презентация
материализуется как обычная, полностью независимая копия в локальном
хранилище устройства (тот же код, что у импорта файла — `natcom:use-template`
переиспользует `materializeProjectCopy` из `electron/natcom/ipc.js`), после
чего её можно свободно редактировать, не трогая исходный шаблон.

## Формат

Каждый файл `NN-slug.natcom.json` — валидный `NatComProject`
(`packages/shared/src/naturalCommunities/model/schema.ts`), проходящий
`parseNatComProject()` + `assertProjectReferencesExist()` против реальной
`packages/natcom-library`. `ownerId`/`organizationId` в файле — заглушка
(`"template"`), не используется: при материализации подставляется реальный
контекст текущего устройства/лицензии.

## Состав (7 сообществ, по объектам библиотеки T5-102)

| Файл | Сообщество | Объектов на сцене |
|---|---|--:|
| `01-les.natcom.json` | Лес | 14 |
| `02-arktika.natcom.json` | Арктика | 11 |
| `03-tundra.natcom.json` | Тундра | 14 (включая песца, переиспользованного из «Арктики») |
| `04-taiga-sibirskaya.natcom.json` | Тайга сибирская | 14 |
| `05-taiga-dalnevostochnaya.natcom.json` | Тайга дальневосточная | 19 |
| `06-step.natcom.json` | Степь | 9 |
| `07-pustynya.natcom.json` | Пустыня | 9 |

Раскладка объектов на сцене — детерминированный алгоритм по категории
(млекопитающие — нижняя треть крупнее, птицы — верх/середина, растения/
земноводные/пресмыкающиеся — низ, за животными), не ручная расстановка
художником — рабочий MVP-вариант «плаката», который педагог может
скорректировать после того, как откроет презентацию (объекты полностью
перетаскиваемы и редактируемы, как у любой пользовательской презентации,
Эпик 7).

## Правила

- Имя файла: `NN-slug.natcom.json`, `NN` — порядок в списке.
- `libraryObjectId` каждого объекта обязан существовать в
  `packages/natcom-library/index.json` на момент сборки — потребители
  обязаны валидировать через `assertProjectReferencesExist`, не читать
  файлы как доверенные данные напрямую.
