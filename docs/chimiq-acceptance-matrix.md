## 4. Открытые расхождения

Перечислены отдельно, чтобы не растворялись в таблице. Каждое требует
решения человека — разработчик закрыть их не может.

### 4.1. Изображение к КАЖДОМУ вопросу (FR-008, FR-015) — ЗАКРЫТО 2026-09-16

ТЗ буквально требует «наличие изображений ко всем вопросам». Кроме
общей картинки-карты уровня (интерактивное поле) каждый из 168 вопросов
теперь показывает ещё и отдельное изображение над текстом вопроса —
нейтральную иллюстрацию по теме вопроса (`questionThemeImages.ts`).

**Осознанное отклонение от буквы ТЗ, решение пользователя**: это НЕ
персональная иллюстрация под каждый конкретный ОТВЕТ, а общая картинка
на тему (6 тем, ~28 вопросов на тему). Причина — проверено на 5 живых
примерах перед принятием решения (см.
`docs/chimiq-question-illustrations-decision.md`): для вопросов вида
«как это называется»/«какой символ»/«какая формула» (подавляющее
большинство банка) точная иллюстрация ответа либо содержит его
буквально (например молекула воды с подписями O/H рядом с вопросом
«формула воды?»), либо сильно на него намекает (рисунок именно колбы
рядом с вопросом «в какой посуде?») — то есть спойлерит игру, а не
иллюстрирует её. Нейтральная картинка по теме формально закрывает
требование «изображение к каждому вопросу» без порчи игрового процесса.

### 4.2. Windows 7+ без установки продукта (FR-018)

Тот же класс расхождения, что у alphabet/words/rusiq. ТЗ требует
отдельный файл, запускаемый на Windows 7+ **без установки продукта**.
Архитектура KIOSK player — установленное приложение с виджетами внутри
одного плеера, не отдельный автономный лаунчер на файл. Реализовано как
обмен файлом `.chimiq.json`, открываемым ТЕМ ЖЕ уже установленным
плеером KIOSK — то есть требование выполнено в духе «обмен викторинами
между пользователями» (FR-013), но не в букве «без установки, на
Windows 7».

Отдельно: Windows 7 недостижим технически — Electron не поддерживает
Windows 7/8 с версии 23, плеер KIOSK собран на Electron 39.

**Требуется решение:** согласовать Windows 10+ и «обмен через
установленный плеер» как целевую трактовку, либо заказывать отдельный
автономный Windows 7-совместимый лаунчер вне архитектуры KIOSK.

### 4.3. Автообновление (FR-021) — отсутствует на платформе

Механизма нет в KIOSK в целом, не только в этом виджете. Закрывается
платформенной работой, не кодом виджета.

### 4.4. Точность содержания (весь банк вопросов, ТЗ раздел 10) — ЧАСТИЧНО ЗАКРЫТО 2026-09-15

Все 168 вопросов написаны как оригинальный контент (не перенос из
эталона). **Проведена методическая рецензия** специально созданным
агентом `chemistry-content-reviewer` (методист-предметник по химии) —
полный отчёт в `docs/chimiq-content-review-2026-09-15.md`. Найдено и
**исправлено 5 CRITICAL фактических ошибок** (неверная атрибуция
исторических открытий Кекуле/Кюри/Фарадею, ложная этимология единицы
«моль», некорректное определение оксидов) и **1 из 2 HIGH-находок**
(прямое противоречие между `q74`/`q99` по авторству закона сохранения
массы) — правкой текста вопросов, без изменения зафиксированных ответов.

**Остаётся открытым:**
- `chimiq-q1` (HIGH, неоднозначный ответ) — правка потребовала бы
  перерисовки тайла на картинке уровня, не сделано в этом проходе.
- 18 MEDIUM-находок о калибровке уровня сложности/темы — в т.ч. системная:
  ≈20% вопросов уровня 3 («Профессионал») по факту соответствуют базовому
  школьному материалу. Требует решения методиста, не изменено
  односторонне разработчиком.
- 10 LOW-находок (точечные уточнения формулировок/подсказок).

**Важно:** это рецензия одного экспертного агента, не консенсус
нескольких методистов-людей. Для контента, который пойдёт в печать/
официальное использование, рекомендуется вторая независимая проверка
человеком-химиком.

**Методологический урок**: прежние живые прогоны (14-15.09.2026, строка
выше) кликали по `correct-point` напрямую через
`document.querySelector(...).click()` в `Runtime.evaluate` — это
срабатывает НЕЗАВИСИМО от того, виден ли элемент физически в окне
(в отличие от клика мышью по экранным координатам). Поэтому баг не
проявился в предыдущих прогонах, хотя они формально были «живыми
CDP-проверками» на реально собранном `.exe`. Полноценная живая проверка
интерактивного поля с большим числом кликабельных зон должна сверять
`getBoundingClientRect()` каждой точки с `window.innerHeight/innerWidth`
явным замером geometry, а не только успешностью programmatic-клика.
