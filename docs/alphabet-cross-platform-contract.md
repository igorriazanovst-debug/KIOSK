# Контракт двух платформ: виджет «АзбукоСлов» (Тип 3)

**Зачем документ.** ТЗ строка 67 требует и Windows, и Android. Android реализуется **отдельным нативным приложением**, а не веб-обёрткой поверх этого кода (решение от 08.09.2026). Значит правила игры будут написаны второй раз, на другом языке, другим человеком.

Совместимость двух реализаций обеспечивается **не общим кодом рантайма**, а общим контрактом: одинаковые форматы данных, одинаковые правила, одинаковая раскладка файлов. Этот документ — сам контракт; `packages/shared/src/alphabet/conformance/vectors.json` — его машинно проверяемая часть.

**Почему так, а не общий код.** Общий код между Electron и нативным Android означал бы веб-обёртку внутри Android-приложения. Разбор эталона ОС3 показал, к чему это приводит: продукт на Electron 6 с Chromium 76 — это браузер 2019 года в поставке 2026-го, со всеми его дырами. Для Android решено писать нативно.

## 1. Что обязано совпадать

| Что | Где зафиксировано | Чем проверяется |
|---|---|---|
| Раскладка файлов контента | `model/resources.ts` | векторы, раздел `resources` |
| Формат манифеста пакета | `model/schema.ts` | векторы, раздел `libraryValidation` |
| Формат статистики и правила слияния | `game/statistics.ts` | векторы, раздел `statistics` |
| Правила редактора контента | `store/contentRules.ts` | векторы, раздел `contentRules` |
| Пригодность слова этапу | `model/graph.ts` | векторы, раздел `stageEligibility` |
| Готовность своего слова | `store/contentRules.ts` | векторы, раздел `readiness` |
| Формат архива комплекта | `electron/alphabet/setArchive.js` | раздел 5 ниже |

## 2. Что совпадать НЕ обязано

- **Внешний вид.** Размеры, цвета, расположение кнопок — дело платформы. На Android свои правила про отступы и целевой размер нажатия.
- **Случайный отбор заданий.** Зависит от генератора случайных чисел; требовать побитового совпадения бессмысленно. Совпадать обязаны **свойства** отбора: восемь вариантов, верный ровно один, односложное слово не попадает на этапы 2 и 3.
- **Способ хранения.** Здесь файлы в `%ProgramData%`, на Android — своё хранилище приложения. Важен формат данных, а не способ их положить.
- **Запись голоса.** Здесь MediaRecorder в рендерере, на Android — платформенный API. Важен формат файла (см. раздел 4).

## 3. Раскладка файлов контента

Единый ключ — транслитерированный идентификатор слова.

```
img/<id>.svg               иллюстрация слова
media/<id>.mp3             слово целиком
media/<id>_bgn.mp3         слово без последнего слога
media/<номер буквы>.mp3    произношение буквы, 1.mp3 … 33.mp3
media/<слог>.mp3           произношение слога
```

**Буква адресуется номером в алфавите, а не самой буквой.** От номера не зависит ни кодировка, ни регистр, ни нормализация Unicode — «Ё» в разных системах может быть одним символом или двумя.

**Слова, слоги и буквы делят каталог `media/`.** Это черта эталонной раскладки, и она же её слабое место: односложное слово «Йод» (`jod`) и слог `jod` дают один путь. Реализация обязана иметь проверку коллизий (`checkPathCollisions`): коллизия односложного слова с собственным слогом безвредна (один и тот же звук), любая другая — дефект сборки.

**Транслитерация:** правила эталона (`avtobus`, `apel_sin` — мягкий знак `_`, `mysh_`) с одним отступлением — **Э даёт `eh`, а не `e`**. Без этого слог «э» и слог «е» получают один идентификатор, то есть один файл на два разных звука.

## 4. Форматы файлов

| Что | Формат | Примечание |
|---|---|---|
| Иллюстрации поставки | SVG | сейчас внутри растр в `data:image/webp` — обёртка временная, но **рендерер SVG на Android обязан уметь встроенный WebP** |
| Озвучка поставки | MP3 | |
| Картинки педагога | PNG, JPEG, GIF, WebP, SVG | проверяется по сигнатуре первых байтов, не по расширению |
| Записи педагога | WebM, MP3, WAV, OGG, MP4 | здесь пишется WebM; принимаются все пять |

**Имя файла медиа педагога — 32 hex-символа (начало sha256 содержимого) плюс расширение.** Это даёт дедупликацию и снимает вопрос обхода пути: имя не приходит от пользователя.

**Имя файла записи голоса — `<род>-<id>.webm`**, где род это `word`, `bgn` или `syllable`. Записи адресуются идентификатором сущности, а не хешем: две записи одного слова разными голосами должны остаться разными файлами.

## 5. Формат архива комплекта (`.kaset`)

ZIP со строго определённым составом. Любой посторонний файл — отказ разбора, а не молчаливый пропуск.

```
manifest.json              { formatVersion: 1, exportedAt }
set.json                   { title, wordIds[], words[], syllables[] }
media/<32hex>.<ext>        картинки своих слов
voice/<род>-<id>.webm      записи
```

**Слоги едут вместе со словами.** Своё слово ссылается на слоги, которые могут быть своими же; без них слово на принимающем устройстве окажется сломанным.

**Поставочные слова НЕ едут** — едет только идентификатор. На принимающем устройстве слово берётся из его собственного пакета контента; если пакет другой версии и слова нет, оно выпадает, а импорт продолжается. Отказ только если осталось меньше двух слов.

**Обязательная оборона при импорте** (ТЗ раздел 9):

1. Белый список **точных** имён, а не проверка «путь не содержит `..`»;
2. Заявленный размер проверяется до открытия потока **и** отдельно считаются реально прочитанные байты;
3. Каждый файл медиа проверяется по **сигнатуре содержимого**, а не по имени.

**Идентификаторы приезжего контента перевыдаются**, слог с тем же написанием переиспользуется, конфликт названий разрешается переименованием.

## 6. Идентификаторы

| Вид | Форма | Пример |
|---|---|---|
| Поставочный | транслитерация, `[a-z0-9_]{1,40}` | `avtobus`, `apel_sin` |
| Свой (педагога) | `u` + 16 hex | `u0123456789abcdef` |

**Запрещено не «начинаться с u», а совпадать ПО ФОРМЕ.** Слова «Утка», «Улитка», «Ухо» дают `utka`, `ulitka`, `uho` — совершенно законные поставочные идентификаторы.

Свои и поставочные сущности лежат в **одних списках**, поэтому пакет обязан принимать обе формы. Разводятся они формой идентификатора, а не расположением.

## 7. Статистика

```jsonc
{ "<профиль>": { "<номер буквы>": { "lastSession": [верно, всего], "total": [верно, всего] } } }
```

**Последняя сессия ЗАМЕЩАЕТСЯ, итог НАКАПЛИВАЕТСЯ.** Буквы, которых в партии не было, **обнуляют сессию**, но сохраняют итог.

**Буква без ответов даёт `null`, а не ноль** при построении графика. Ноль читается как «отвечал и всё неверно» — ровно противоположно правде.

**Какой букве засчитывается ответ:** на этапе 1 — первой букве слова, на этапах 2 и 3 — первой букве подбираемого слога. Один ответ — ровно одна буква.

**Разбор терпимый:** битая запись по одной букве отбрасывается, остальные выживают.

## 8. Как пользоваться векторами

```
cd packages/shared
npm run build
node src/alphabet/conformance/generate.mjs   # перегенерировать
npm test                                      # проверить соответствие
```

`vectors.json` — обычный JSON, читается любой платформой. Android-реализация прогоняет ту же таблицу своими средствами.

**Векторы фиксируют текущее поведение, а не доказывают его правильность.** Если правило придётся менять осознанно, векторы перегенерируются, и разница будет видна в диффе `vectors.json` — то есть попадёт на ревью, а не проскользнёт.

---

## 9. Чего в контракте нет

- **Экранов и переходов между ними.** Набор экранов одинаков по смыслу, но их устройство — дело платформы.
- **Пароля педагога.** Правила общие (`teacherGate.ts`), но хеш и соль — платформенные: пароль, заданный на планшете, не должен открывать доску, это разные устройства.
- **Рассадки за столом.** На планшете её нет вовсе.
