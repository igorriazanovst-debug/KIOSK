# Программа и методика испытаний: виджет «Я знаю много слов» (Тип 2)

**Документ требуется ТЗ:** раздел 13, позиция «программа и методика испытаний». Опирается на раздел 12 ТЗ, который задаёт обязательный состав проверок.

**Что это за документ.** Не отчёт о пройденных проверках (отчёт — по итогам приёмочного прогона, трассировка — в `words-acceptance-matrix.md`), а описание **как** проверять: что считается проверкой, в каком окружении, с каким результатом. Нужен, чтобы приёмку можно было повторить чужими руками и получить тот же ответ.

**Дата:** 11.09.2026.

---

## 1. Три уровня проверки и почему их именно три

Этот проект уже получал урок на предыдущем виджете: у «Хронолинии» сборка и 122 теста проходили чисто, а фича защиты паролем **не работала для пользователя с первого дня** — точка входа в неё была физически недостижима. Шесть реальных дефектов не поймали ни `tsc`, ни `vite build`, ни тесты.

Отсюда разделение, обязательное к соблюдению:

| Уровень | Что проверяет | Чем | Что НЕ докажет |
|---|---|---|---|
| **Домен** | Правила игры, схемы, раскладку файлов | Юнит-тесты, TDD | Что до этих правил вообще можно доклик­нуться |
| **Платформа** | Хранилище, IPC, архив комплекта | Интеграционные тесты на временном каталоге | Что кнопка вызывает нужную ручку |
| **Интерфейс** | Всё, что пользователь нажимает, вводит, растягивает | **Живой прогон на работающем приложении** | — |

**Правило:** функция, которую пользователь трогает руками, не считается готовой, пока не проверена живым запуском. Зелёная сборка готовностью не является.

## 2. Окружение испытаний

### 2.1. Автотесты

```
packages/shared    npm install && npm test     # домен игры
packages/player     npm install && npm test     # платформа и рантайм
```

Обязательно перед запуском: проверить симлинк `node_modules/@kiosk/shared` (его сносит `npm install`, npm workspaces в проекте нет). Без симлинка тесты падают на импортах, и это **не** дефект продукта.

### 2.2. Живой прогон интерфейса

Два варианта, от более достоверного к менее:

**А. Внутри Electron (предпочтительно, покрывает IPC и протоколы доставки файлов).**

1. Сохранить `packages/player/electron/project.json`, подменить на проект с одним виджетом типа `words`.
2. `npx vite build` в `packages/player` (перед этим собрать `packages/chrono-ui` — плеер без него не собирается).
3. Запустить `node_modules/electron/dist/electron.exe . --remote-debugging-port=9222`.
4. Подключиться по Chrome DevTools Protocol, читать состояние через `Runtime.evaluate`.
5. **Вернуть `project.json` через `git checkout --` сразу после прогона.**

**Б. Рендерер в браузере без Electron (когда окно создать нельзя — например, в неинтерактивном сеансе).**

1. Собрать отдельную временную точку входа (`build.rollupOptions.input` на свой HTML), монтирующую нужные экраны с подставными обработчиками.
2. Открыть готовый файл в Chrome: `--headless=new --remote-debugging-port=9333 --disable-web-security --allow-file-access-from-files` (без последних двух флагов браузер заблокирует модульные скрипты с `file://`).
3. Драйвить по CDP.
4. **Удалить временную точку входа и конфиг сразу после прогона.**

Вариант Б проверяет интерфейсную логику, но **не** проверяет IPC, протоколы `wordslib://`/`wordsuser://` и системные диалоги — в нём `window.wordsAPI` отсутствует. Результат прогона обязан указывать, каким вариантом он получен.

### 2.3. Приёмы, без которых прогон даёт ложный результат

- **События — настоящие, не синтетические.** Кнопки слушают `onPointerDown`/`onPointerUp`, поэтому слать нужно `Input.dispatchMouseEvent`, а не `element.click()` и не `new Event('click')`. Диспатч `'click'` по кнопке, висящей на `onMouseDown`, не сработает — и это будет ошибкой теста, не приложения.
- **Ввод в `<input>`** — только через сеттер прототипа плюс `dispatchEvent(new Event('input', {bubbles:true}))`, иначе React не увидит изменение. Имя игрока, впрочем, набирается **экранной клавиатурой**, то есть нажатиями по её кнопкам.
- **Текст в ProseMirror** — через CDP `Input.insertText`; синтетические DOM-события он не распознаёт.
- **`window.prompt()` в Electron не реализован вообще.** Если он встретился в коде — это дефект, а не то, что нужно эмулировать. `window.confirm()` работает и ловится через `Page.javascriptDialogOpening`.
- **Озвучка** проверяется обёрткой `Audio.prototype.play` со сбором `src` — на слух проверять не нужно.
- **Повороты рассадки** снимаются вычисленными стилями: `matrix(0,1,-1,0)` = 90°, `matrix(-1,0,0,-1)` = 180°, `matrix(0,-1,1,0)` = −90°.
- **Ресайз** — `Emulation.setDeviceMetricsOverride` плюс ручной `window.dispatchEvent(new Event('resize'))`; двигать окно операционной системы не нужно.
- **Микрофон через CDP достоверно не эмулируется** — только реальное устройство, и отдельно устройство без микрофона.
- **Хранилище общее на машину.** Тест IPC без подмены каталога (`sharedDirOverride`) пишет в реальные `C:\ProgramData\kiosk-words` — то есть в данные педагога. Один такой тест уже был написан неправильно и принял два «устройства» за одно.

## 3. Состав испытаний по разделу 12 ТЗ

### 3.1. Функциональное тестирование всех FR

Каждое требование FR-002…FR-024 должно иметь минимум один тест-кейс. Соответствие «требование → чем закрыто → чем проверено» ведётся построчно в `words-acceptance-matrix.md`; дублировать его здесь нельзя, иначе документы разойдутся.

### 3.2. Установка, первый запуск, обновление, удаление

| Проверка | Ожидаемый результат |
|---|---|
| Сборка `.exe` с виджетом через админку, установка на чистую машину | Установка без ошибок |
| Первый запуск | Каталог данных создан сам, правка системных файлов не потребовалась |
| Обновление поверх установленной версии | Профили, статистика и свои слова на месте |
| Удаление приложения | Приложение удалено, каталог данных сохранён |
| Удаление каталога данных вручную | Следующий запуск начинает с чистого состояния, без ошибок |

**Пункт «обновление» на 11.09.2026 непроверяем:** механизма автообновления нет (FR-023).

### 3.3. Сохранение и повторное открытие данных

| Проверка | Ожидаемый результат |
|---|---|
| Создать двух игроков, закрыть приложение, открыть | Оба на месте и в интерфейсе, и в файле |
| Изменить громкость, перезапустить | Значение сохранилось |
| Пройти тему на «золото», перезапустить | Достижение на месте |
| Пройти ту же тему хуже | Ступень **не понизилась** |
| Создать своё слово с записью, перезапустить | Слово и запись на месте |
| Выключить питание во время сохранения | Файл либо старый целый, либо новый целый; обрывка нет |

### 3.4. Заявленные ОС и типы устройств

| Устройство | Как проверять | Состояние |
|---|---|---|
| ПК, Windows 10 | Установка, партия, редактор контента | Проверено на машине разработки |
| Windows 7 / 8 | Установка | **Не поддерживается платформой** (Electron 39) |
| Интерактивная доска | Партия пальцем, экранная клавиатура | Не проверялось |
| Интерактивный стол | Партия вчетвером с четырёх сторон, повороты | Не проверялось |
| Планшет Android | Партия | Приложение не начато |

Проверка сенсорного ввода пальцем на реальной панели обязательна и ничем не заменяется: CDP эмулирует pointer-события, но не физическое касание несколькими пальцами, не ложные срабатывания у края панели и не задержки отклика дешёвого тачскрина.

### 3.6. Комплектность встроенного контента

| Проверка | Ожидаемый результат | Состояние на 14.09.2026 |
|---|---|---|
| Число слов | ≥ 250 | **256** ✅ |
| Число тем | ≥ 15, названия уникальны | **16** ✅ |
| У каждого слова есть иллюстрация | Да | **256 из 256**, заглушек нет ✅ |
| У каждого слова полный набор записей по заявленной схеме | Да | **800 файлов**, комплектность полная ✅ |
| Обложка у каждой темы | Да | **16 из 16** ✅ |
| Вводная часть у каждой темы | Своя, а не общий шаблон | **16 из 16** ✅ |
| Корректура текстов | Опечаток нет | Не проводилась |
| Правовой статус материалов | Подтверждён | Картинки нарисованы нейросетью, озвучка синтезирована — решение за заказчиком |

**Отдельная проверка, которой не было: НАЗЫВАЕМОСТЬ КАРТИНКИ.** Ребёнок ищет
картинку по услышанному слову, и если нарисованное можно назвать иначе, он
ошибётся, будучи правым. Ни комплектность, ни тесты этого не видят — только
просмотр готовых изображений глазами.

Так 14.09.2026 была снята целая тема «Части тела»: замысел «ребёнок целиком,
нужная часть ярко выделена» на бумаге выглядел верным, а на готовых карточках
почти каждая читалась как «мальчик» или «девочка». Заменена на «Насекомых».
Тогда же на двух обложках нашлись надписи латиницей, хотя стиль их запрещает.

| Что проверять глазами | Почему |
|---|---|
| Каждую карточку темы подряд | Слово должно быть ЕДИНСТВЕННЫМ названием того, что нарисовано |
| Пары внутри одной темы | Дистракторы берутся сначала из своей темы: «Сапоги» и «Ботинки» рядом сделают шаг нечестным |
| Надписи на картинках | Стиль их запрещает, но модель их иногда рисует; латиница в русском пособии — брак |

Несоответствие манифесту — **ошибка сборки пакета контента, а не предупреждение**. У эталона ОС3 в поставке не хватало двух mp3, и дефект дожил до продакшена незамеченным, потому что вариант озвучки выбирается случайно из имеющихся.

### 3.7. Совместная игра: задания игроков не повторяются

Дети за одним столом видят задания друг друга, и одно и то же слово у двоих
сразу — жалоба, которую педагог услышит на первом же занятии. В темах мало
слов (сейчас по 5, у эталона 10–21 при 20 шагах), поэтому совпадения были не
редкостью: до правки от 13.09.2026 слова раздавались каждому игроку
независимо, и **повтор выпадал в 51 % кругов** — замерено на настоящих темах,
24 000 кругов, от двух до четырёх игроков.

**Круг** — подряд идущие ходы всех игроков: первый шаг каждого, затем второй
шаг каждого и так далее.

| Проверка | Ожидаемый результат | Уровень |
|---|---|---|
| Партия вдвоём, втроём, вчетвером: слова в каждом круге | Все разные | Тест + живой прогон |
| Слова одного игрока подряд | Одно слово не выпадает двумя его шагами подряд | Тест |
| Одиночная партия | Прежнее правило цело: слово не встаёт двумя шагами подряд | Тест |
| Расход темы за партию | Каждое слово темы использовано одинаковое число раз с точностью до единицы — «любимых» слов нет | Тест |
| Тема из 4 слов, играют четверо | Круг чист; повтор у одного игрока между кругами **допускается** — при запасе, равном числу игроков, развести оба правила нельзя | Тест |
| Тема из 3 слов, играют четверо | Партия идёт и не виснет; повтор в круге **неизбежен** и дефектом не считается | Тест |

**Чем проверяется в коде:** `shared/src/utils/turnDeal.test.ts` — 13 тестов на
сам алгоритм раздачи; `shared/src/words/game/session.test.ts` — свойства через
`buildSession`, на 100 зёрнах каждое.

**Почему через `buildSession`, а не только через раздачу.** Верный алгоритм
можно подключить неверно — например, разложить шаги по игрокам не в том
порядке, в каком они ходят. Тогда свойство раздачи до стола не дойдёт, а тест
на сам алгоритм останется зелёным.

**Почему на многих зёрнах.** Прежняя раздача на отдельных зёрнах тоже давала
чистый круг. Один прогон здесь ничего не доказывает.

Правило общее с виджетом «АзбукоСлов» (Тип 3) и живёт в одном модуле
`shared/src/utils/turnDeal.ts`: два движка с собственными копиями подобного
алгоритма разошлись бы молча — раздача не падает, она просто становится хуже.

## 4. Критерии приёмки

Виджет считается принятым, когда одновременно:

1. Все FR раздела 5 ТЗ закрыты либо осознанно отклонены с письменным обоснованием (`words-acceptance-matrix.md`).
2. Автотесты домена и платформы зелёные.
3. Интерфейс пройден живым прогоном **внутри Electron** на реальной сборке.
4. Партия сыграна на реальной интерактивной панели пальцем и на столе с четырёх сторон.
5. Контент прошёл проверку комплектности и корректуру, реестр источников и лицензий заполнен.
6. Негативные сценарии раздела 3.5 пройдены.
7. Комплект документов раздела 13 ТЗ передан.
8. Критических дефектов, блокирующих обязательную функцию, нет (прямое требование раздела 12).

**Любой из пунктов 3–5, закрытый «по здравому рассуждению» вместо фактической проверки, делает приёмку недействительной.** Это не формальность: все шесть дефектов предыдущего виджета жили именно в зоне, которую казалось логичным не проверять.
