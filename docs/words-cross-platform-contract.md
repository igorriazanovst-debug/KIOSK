# «Я знаю много слов» (Тип 2) — контракт двух реализаций

Продукт по ТЗ (строка 44) выходит на Windows и Android. **Android реализуется отдельным нативным приложением, а не поверх кода Electron-плеера** (решение от 08.09.2026). Значит игровые правила будут написаны дважды, на разных языках.

Этот документ и лежащие рядом сверочные векторы — единственное, что удерживает две реализации от расхождения. Общего кода между ними нет.

| | Windows | Android |
|---|---|---|
| Оболочка | Electron-плеер KIOSK, виджет типа `words` | Отдельное нативное приложение |
| Игровая логика | `packages/shared/src/words/**` (TypeScript) | Пишется заново |
| Хранилище | JSON-файлы в общем на машину каталоге | На усмотрение реализации |
| Контент | пакет `words-library` через `extraResources` | тот же пакет, доставка на усмотрение |

**Что обязано совпадать:** форматы файлов, правила поведения и тексты сообщений пользователю. **Что не обязано:** язык, каркас интерфейса, способ хранения, генератор случайных чисел.

---

## 1. Сверочные векторы

`packages/shared/src/words/conformance/vectors.json` — таблица «вход → ожидаемый результат». Обе реализации обязаны давать ровно эти значения.

Покрыто: раскладка файлов ресурсов, три схемы озвучки, пороги достижений, все 16 переходов монотонного обновления ступени, правила имени игрока **вместе с текстом отказа**, запись достижения, список случаев, которые пакет контента обязан отвергать.

Векторы сняты с реализации на TypeScript и фиксируют её как контракт. Это не доказательство правильности — это фиксация: расхождение становится падением теста, а не тихой разницей в поведении на уроке. Перегенерация: `npm run build && node src/words/conformance/generate.mjs` в `packages/shared`; менять их можно только сознательно, вместе с обеими реализациями.

---

## 2. Формат пакета контента

Полностью описан в `packages/words-library/README.md`. Ключевое:

- `index.json` — манифест с `schemaVersion`, `audioScheme`, темами и словами;
- **идентификатор слова — четыре цифры**: две первые это номер темы, две последние — номер слова внутри темы. Он же имя файла иллюстрации, он же имя папки озвучки, поэтому путь любого ресурса выводится из него одного;
- раскладка файлов и правила комплектности — в векторах, раздел `resources`.

Пакет один и тот же для обеих платформ. Различаться может только способ доставки (в `.exe` через `extraResources`, в APK — в ассетах приложения).

## 3. Формат локальных данных

Четыре независимые сущности. Формат обязателен к совпадению — иначе данные, снятые с планшета, не откроются на ПК.

```jsonc
// профили детей
[ { "id": "<уникальный>", "name": "Аня", "createdAt": "<ISO-8601>" } ]

// достижения: профиль → тема → ступень
{ "<profileId>": { "digits": "gold" } }        // wooden | silver | gold

// настройки занятия
{ "schemaVersion": 1, "volume": 70, "device": "board", "levelOverrides": { "0000": 2 } }
//                    0..100         tablet|board|table   слово → уровень 0|1|2

// свои слова педагога
[ { "id": "u<hex>", "name": "…", "level": 9, "imageFile": "…", "audioFile": null } ]

// свои комплекты: могут смешивать поставочные и свои слова
[ { "id": "set-<hex>", "title": "Урок", "wordIds": ["0200", "u<hex>"] } ]
```

**Файлы медиа** именуются по хешу содержимого (`sha256`, первые 32 hex-символа) плюс расширение. Имя не берётся от пользователя — это разом снимает обход пути, коллизии имён и даёт дедупликацию. Приходящий файл проверяется по **сигнатуре содержимого**, а не по расширению: переименованный `.exe` с расширением `.png` обязан быть отвергнут.

**Целостность связей:** удаление своего слова вычищает его из **всех** комплектов и удаляет его файлы, если на них никто больше не ссылается. Комплект со ссылкой на удалённое слово — это партия, падающая посреди урока.

Требования к записи: **атомарность** (временный файл + переименование либо эквивалент) — прямое требование ТЗ раздела 7. Повреждённый файл — явная ошибка с сообщением, **а не «список пуст»**: молча обнулившийся список профилей педагог прочитает как потерю работы детей.

## 4. Правила игры

Проверяемое — в векторах; здесь то, что векторами не выражается.

**Партия.** 20 шагов на игрока по умолчанию. Ход поочерёдный: сначала все игроки делают свой первый шаг, потом второй — а не один проходит партию, пока остальные ждут.

**Шаг.** Загаданное слово плюс дистракторы. Дистракторы берутся сначала из своей темы (ближе по смыслу, выбор осмысленнее), при нехватке добираются из остальных. Инварианты, которые обязана обеспечить любая реализация со своим генератором случайности:

- загаданное слово всегда среди вариантов;
- варианты не повторяются внутри шага;
- **одно и то же слово не загадывается два шага подряд** (исключение — тема из одного слова);
- слов в теме почти всегда меньше, чем шагов: список перемешивается и повторяется;
- **в совместной игре задания раздаются на всю партию сразу, в порядке хода** — см. ниже.

**Совместная игра: задания игроков не повторяются.** Раздавать каждому игроку
независимый список нельзя. Дети за одним столом видят задания друг друга, а
слов в теме мало — при независимой раздаче повтор в круге выпадал в 51 %
кругов (замерено на настоящих темах). Круг — подряд идущие ходы всех игроков.

Обязательные свойства раздачи:

- в пределах одного круга задания игроков не повторяются, если слов в теме не
  меньше, чем игроков;
- одному игроку одно слово не выпадает двумя его шагами подряд, если слов
  строго больше, чем игроков;
- тема расходуется равномерно: за партию каждое слово использовано одинаковое
  число раз с точностью до единицы.

**Требовать, что слово повторится только после исчерпания темы, нельзя:**
раздача идёт перестановками темы, и на стыке двух проходов слово с конца
одного законно оказывается недалеко от себя же в начале следующего.

**Вырожденные случаи** обязаны вести себя одинаково: при теме ровно из числа
игроков держится только первое свойство; при теме меньше числа игроков не
держится и оно — четырём игрокам не раздать три разных слова, и это не дефект.

Эталонная реализация правила: `shared/src/utils/turnDeal.ts`, общая с виджетом
«АзбукоСлов» (Тип 3).

**Ответ.** Неверный: счётчик ошибок шага растёт, карточка убирается с экрана, ход **остаётся**. Верный: счётчик обнуляется, шаг закрывается, ход переходит. Повторное касание уже отвергнутой карточки и любой ответ после конца партии **игнорируются, а не считаются ошибкой** — на сенсорной панели двойное касание норма, и штрафовать за него ребёнка нельзя.

**Уровни различаются механикой, а не «сложностью вопросов»:**

| Уровень | Механика |
|---|---|
| Ⅰ (`0`) | Силуэт загаданного предмета показан — сопоставление по форме |
| Ⅱ (`1`) | Силуэта нет, опора только на прозвучавшее слово |
| Ⅲ (`2`) | Отвечается нажатием, как Ⅱ, и отличается от него только сценарием озвучки. Перетаскивание **убрано** решением заказчика от 13.09.2026; для ребёнка Ⅱ и Ⅲ сейчас почти одинаковы, и это осознанное состояние, а не недоделка |
| Своё слово (`9`) | Отдельный сценарий озвучки: фразовых вариантов нет, есть только запись педагога |

**Достижения.** Три ступени, обновление **монотонное** — результат можно только улучшить. Один неудачный заход в конце дня не должен стирать заработанное золото. Пороги — в векторах; они выбраны разработчиком и **ждут подтверждения методиста**, менять их нужно одновременно в обеих реализациях.

**Озвучка.** Реплики играют последовательно, не наслаиваясь. У партии есть идентификатор, и реплика, начатая в предыдущей партии, **отбрасывается**, а не доигрывается: иначе звук прошлой партии догоняет следующую и произносит чужое слово. Отсутствующий файл озвучки очередь не роняет.

## 5. Сеть

ТЗ разрешает сетевое соединение и нигде его не запрещает, но ставит границу (разделы 7, 9, 11, 12):

- **на сеть можно вешать** — активацию лицензии, автообновление (FR-023), догрузку контента;
- **на сеть нельзя вешать** — занятие: игра, профили, статистика, свои слова работают офлайн;
- отсутствие сети — **штатная ситуация** и обязательный тест-кейс приёмки, а не аварийная.

Отдельно: у эталона ОС3 Android отсутствует в фиде обновлений, и автообновление на планшетах не работает вообще. Нативная реализация обязана закрывать FR-023, иначе строка 62 пройдёт приёмку только для Windows.

---

## 5.1. Формат записей педагога

Поставочный контент — mp3. **Записи, сделанные педагогом на устройстве, будут в другом формате**, и он зависит от платформы: Chromium в Electron пишет `audio/webm;codecs=opus` (проверено спайком 08.09.2026), нативная Android-реализация будет писать своё (скорее всего m4a/AAC).

Отсюда требование: **каждое приложение обязано проигрывать файлы, записанные другим.** Расширение хранится в имени файла (`audioFile` в записи своего слова), формат не предполагается по умолчанию. Если перенос своих слов между платформами станет сценарием, потребуется либо общий формат записи, либо конвертация при импорте — это открытый вопрос, а не решённый.

---

## 6. Тексты пользователю

Сообщения об ошибках — часть контракта, а не оформление: педагог у доски видит их на обеих платформах и должен получать одно и то же. Точные строки — в векторах (`rules.profileName[].error`).

---

## 7. Что делать при расхождении

Если реализации разошлись — сначала решается, **какое поведение правильное**, и только потом правится код и перегенерируются векторы. Молча подогнать одну реализацию под другую нельзя: векторы для того и существуют, чтобы такое решение принималось явно.
