# Программа и методика испытаний: виджет «ФизАстроIQ» (Тип 11)

**Назначение.** Документ описывает, как проверить соответствие виджета требованиям ТЗ `ТЗ_11_Физ_IQ_Астро_IQ.docx` (FR-002…FR-027, строки 323–348). Каждый пункт приводит: что подготовить, что сделать, что должно получиться.

**Состояние на 20.09.2026.** Разделы 1–6 автоматизированы и проходят: **50 проверок из 50** — в том числе на приложении, установленном из установщика с прода. Раздел 7 выполняется вручную.

**Про нумерацию строк ТЗ.** В подлиннике номер строки-источника стоит ПОСЛЕ критерия приёмки: `ИСТ = 321 + номер FR`.

---

## 0. Подготовка стенда

Испытания проводятся на **собранном** приложении, а не на режиме разработчика: разница между ними уже дважды давала ложный результат на этом проекте.

```sh
cd packages/player && npx vite build
cd ../../docs/tools
./restand.sh stage-physastroiq 9712 kiosk-physastroiq kiosk-physastroiq
```

`restand.sh` снимает предыдущий стенд и **удаляет каталог данных виджета**. Это обязательно: разделы 4 и 5 проверяют поведение при первом запуске (PIN ещё не задан), и на накопленном состоянии они невоспроизводимы.

Данные виджета лежат в `%APPDATA%\kiosk-physastroiq`. Подмена `PROGRAMDATA`, которой пользуются испытания Типов 2, 3 и 4, на виджеты семейства «IQ» **не действует** — они берут `app.getPath('appData')`. Поэтому каталог сносится явно, четвёртым аргументом `restand.sh`.

Автоматический прогон разделов 1–6:

```sh
node physastroiq-accept.mjs 9712 all
```

Ожидаемый вывод последней строкой: `ИТОГ: пройдено 50, не пройдено 0`.

Отдельный раздел запускается номером: `node physastroiq-accept.mjs 9712 3`. Разделы 4–6 предполагают, что перед ними отработали предыдущие (задан PIN, сыграна партия), поэтому по одному их запускают только с чистого стенда и по порядку.

## 2. Партия по физике

**Требования:** FR-006 (327), FR-007 (328), FR-008 (329), FR-012 (333), FR-013 (334), FR-020 (341).

| № | Действие | Ожидаемый результат |
|---|---|---|
| 2.1 | Играть → 1 игрок → имя → «Начинающий» → 5 вопросов | Открылась карта `phys_level1_map.png` |
| 2.2 | Сверить размер загруженной карты | 1800×1200 — совпадает с объявленным в схеме |
| 2.3 | Осмотреть поле | Ровно одна правильная точка |
| 2.4 | Там же | Точек-обманок не меньше 10 (FR-013) |
| 2.5 | Осмотреть заголовок | «Вопрос 1/5» — столько, сколько выбрано (FR-020) |
| 2.6 | Осмотреть таймер | Идёт обратный отсчёт |
| 2.7 | Осмотреть вопрос | Есть кнопка «Показать подсказку» (FR-006) |
| 2.8 | Нажать правильную точку | Ответ засчитан, ход перешёл к «Вопрос 2/5» |
| 2.9 | Нажать «Сдаюсь» | Вопрос пропущен, ход перешёл к «Вопрос 3/5» (FR-007) |
| 2.10 | Досдаться до конца | Показан экран результатов |
| 2.11 | Нажать «Подробнее» | Перечислены вопросы с отметкой верно/неверно и очками (FR-012) |
| 2.13 | Осмотреть строку вопроса | Рядом с текстом — картинка темы по физике; она загружена и целиком лежит в окне (FR-009, FR-016) |

**Про 2.2 отдельно.** Заявленный в схеме размер изображения — это система координат, в которой лежат все точки ответов. Разойдись он с реальным пикселем PNG, точки поедут пропорционально: картинка на месте, вопросы на месте, а нажимать надо рядом с прибором. Ровно так «РусIQ» потерял около пятой части кликабельных вопросов.

**Про 2.13 отдельно.** Картинка темы нейтральная намеренно: на ней нет ни одного объекта, который бывает ответом на карте. При ручной проверке стоит убедиться именно в этом — что эмблема не подсказывает, как выглядит искомая деталь.

**Про 2.8 отдельно.** После ответа поле около секунды держит вердикт и лишь затем показывает следующий вопрос. Проверять результат раньше этого срока бессмысленно — увидите прежний экран.

## 7. Ручные проверки

Эти пункты автоматическому прогону не поддаются и выполняются человеком.

### 7.1. Обмен викторинами (FR-014, строка 335)

1. Открыть каталог, нажать «Импортировать викторину».
2. Выбрать `docs/physastroiq-exchange-check.json` (270 КБ; 12 вопросов, по 4 на уровень; 9 тем; три карты уровней внутри файла).
3. **Ожидается:** викторина появилась в каталоге под своим названием; можно назначить её активной и сыграть партию на каждом из трёх уровней; изображения карт отображаются.

Файл собран инструментом `tools/physastroiq/make-exchange-file.mjs` **средствами самого продукта** — его же экспортёром — и проверен его же импортёром: формат принят, выдан свежий идентификатор, восстановлены все три PNG.

### 7.2. Наложение областей на карту

```sh
cd packages/player
node tools/physastroiq/overlay-structures.mjs physics
node tools/physastroiq/overlay-structures.mjs astro
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/electron.exe \
  tools/physastroiq/render-thematic.cjs "$(pwd -W)/tools/physastroiq/overlay" "$(pwd -W)/tools/physastroiq/overlay"
```

Просмотреть шесть получившихся PNG. **Ожидается:** каждая подписанная область лежит на своём объекте, а не рядом с ним.

Проверка обязательна после любой правки карт уровней. Автоматически её не сделать: прямоугольник с именем «Луна», лежащий на пустом месте рядом с Луной, для любой проверки безупречен. На первом прогоне так нашлись три настоящих дефекта, включая область «Луна в первой четверти», стоявшую рядом с диском.

### 7.3. Повреждённое хранилище

1. Закрыть приложение.
2. Записать в `%APPDATA%\kiosk-physastroiq\userdata.json` произвольный мусор.
3. Запустить приложение.
4. **Ожидается:** на стартовом экране один раз показано предупреждение о том, что сохранённые данные прочитать не удалось и начато с чистого состояния; приложение работает, новые партии сохраняются.

Пункт нужен, чтобы педагог не принял пустую статистику за «ещё не играли».

### 7.4. Содержательная проверка вопросов

Выполняется учителем физики и учителем астрономии. Приложение одинаково исправно засчитает и верный ответ, и неверный, если так написано в банке: **правильность вопросов автоматическим прогоном не проверяется и проверена быть не может.**

Материал для проверки: `packages/player/tools/physastroiq/questions-physics.mjs` и `questions-astro.mjs` — 180 вопросов с ответами и подсказками, в исходном виде, по разделам.

### 7.5. Многопользовательский режим (FR-010, строка 331)

1. Начать партию на 2 игроков, затем на 3.
2. **Ожидается:** ход переходит по кругу; имена игроков видны; на итогах перечислены все участники с очками и долей верных ответов.

## 8. Чего эта программа не покрывает

- **Windows 7 и 8** — плеер на них не запускается (Electron 39). См. матрицу §4.2;
- **запуск экспортированной викторины без установленного продукта** — не реализовано. См. матрицу §4.3;
- **обновление исполняемого файла** — механизм обновляет содержимое проекта, а не саму программу. См. матрицу §4.4;
- **правильность физики и астрономии** — п. 7.4, за методистом.
