# Снимки экранов для пользовательских инструкций

Здесь лежит то, чем сделаны все снимки в `alphabet-user-guide.md` и
`words-user-guide.md`.

**Зачем это в репозитории.** Инструкция со снимками устаревает при первой же
правке интерфейса, и устаревает молча: текст выглядит прежним, а экран уже не
тот. Пересобрать её вручную — час работы и повод не пересобирать. Поэтому
снимки делаются **сценарием**, и сценарий хранится рядом с документом.

То же правило один раз уже пришлось применить к озвучке: первые 618 файлов
контента Типа 3 сделал разовый скрипт, не сохранившийся в репозитории, и
пакет оказался невоспроизводимым. Второй раз наступать на это не будем.

---

## Что чем является

| Файл | Что делает |
|---|---|
| `shoot.mjs` | Проходит сценарий и сохраняет PNG |
| `restand.sh` | Поднимает стенд с **чистого** хранилища |
| `plan-alphabet.json` | Сценарий для «АзбукоСлов» — 21 снимок |
| `plan-words.json` | Сценарий для «Я знаю много слов» — 15 снимков |

## Как пересобрать снимки

```sh
# «АзбукоСлов»
./restand.sh stage-alphabet 9677 kiosk-alphabet
node shoot.mjs plan-alphabet.json

# «Я знаю много слов»
./restand.sh stage-words 9678 kiosk-words
node shoot.mjs plan-words.json
```

Пути в сценариях заданы от каталога, из которого запускается `shoot.mjs`.
Стенд — распакованная сборка плеера с нужным `project.json`.

---

## Решения, которые стоит знать, прежде чем править

**Хранилище подменяется через `PROGRAMDATA`.** Стенд пишет в отдельную папку и
не трогает данные педагога в `C:\ProgramData\kiosk-alphabet`. Без этого съёмка
показывала бы чужие профили, а сброс состояния стирал бы чужую работу.

**Каждый прогон начинается с нуля.** Без сброса второй прогон падает на «такое
имя уже занято» — и это правильно: инструкция не должна собираться из
случайного состояния, накопленного прошлыми запусками.

**Сценарий падает на первой же неудаче** и печатает, что было на экране. Молча
пропущенный шаг дал бы снимок не того экрана под прежней подписью — именно так
инструкции и начинают врать.

**Кадрирование по содержимому.** Снимается не окно целиком, а рамка вокруг
видимых элементов; контейнеры во весь экран отбрасываются по площади (порог
85 % окна), иначе рамка растягивается на всё окно.

**Служебная строка с путём к данным скрывается на время снимка.** Исключить её
из рамки мало — она лежит внутри кадра. На стенде в ней стоит временный
каталог, и в инструкции он только запутает. Это сокрытие технической строки, а
не подмена содержимого, и в самих инструкциях об этом сказано прямо.

**Ответы в игре берутся у самой игры.** Шаг `верно` читает у Типа 3 верный
вариант из `play-expected`; у Типа 2 шаг `верно2` читает загаданное слово с
экрана и переводит его в идентификатор карточки через тот же пакет контента,
которым играет приложение. Ничего не угадывается — снимки сделаны с настоящего
прохождения.

## Язык сценария

```jsonc
{
  "порт": 9677,                    // отладочный порт стенда
  "каталог": "KIOSK/docs/img/...", // куда класть PNG
  "словарь": "words-library/index.json", // только Тип 2
  "пауза": 380,                    // пауза после нажатия
  "неснимать": ["storage-note"],   // что прятать на время снимка
  "шаги": [ /* ... */ ]
}
```

| Шаг | Что делает |
|---|---|
| `{ "клик": "testid" }` | Нажать элемент |
| `{ "ввод": ["testid", "текст"] }` | Набрать в поле (через сеттер прототипа — иначе React не заметит) |
| `{ "жди": 600 }` | Подождать миллисекунды |
| `{ "проверь": "testid" }` | Убедиться, что элемент есть, иначе падение |
| `{ "снимок": "имя", "подпись": "..." }` | Сохранить PNG |
| `{ "целиком": true }` рядом со снимком | Снять окно целиком, без кадрирования |
| `{ "верно": N }` | Тип 3: ответить верно N раз |
| `{ "неверно": true }` | Тип 3: нажать заведомо неверный вариант |
| `{ "верно2": N }` | Тип 2: ответить верно N раз |
| `{ "неверно2": true }` | Тип 2: нажать заведомо неверную карточку |

## Если сценарий упал

Сообщение называет номер шага, сам шаг и печатает текст экрана, на котором всё
остановилось. Обычные причины:

- **изменился `data-testid`** — поправьте сценарий;
- **выбор игрока — переключатель**: повторное нажатие снимает отметку, и
  партия уходит в одиночную;
- **шаг выполнился раньше, чем перерисовался экран** — добавьте `жди`.
