# Тип 6 «Матемашка» — Этап 2a: инструменты-лаборатории «Цепочка» и «Два отрезка» — дизайн

Дата: 2026-09-08
Статус: согласован с пользователем в диалоге, ожидает финального самообзора перед переходом к плану реализации.

## 0. Контекст и место в общем плане

Этап 1 (движок + пилотный контент, `docs/superpowers/specs/2026-09-07-mathmachine-widget-design.md` + `docs/superpowers/plans/2026-09-07-mathmachine-widget-phase1.md`) завершён: финальное ревью всей ветки `feat/mathmachine-widget` пройдено, ветка НЕ смёржена (оставлена как есть по решению пользователя). Из трёх обязательных по ТЗ (FR-023/024) инструментов-лабораторий реализован один — Весы.

По решению пользователя Этап 2 разбит на два независимых под-проекта (свои спека/план/реализация на каждый):

- **Этап 2a (этот документ) — движок**: два оставшихся инструмента, «Цепочка» и «Два отрезка». Это добавка к существующей ветке `feat/mathmachine-widget`, а не отдельная фича — расширяет тот же `packages/shared/src/mathmachine/` и `packages/player/src/mathmachine/`, использует уже реализованные паттерны (Весы как прямой прецедент).
- **Этап 2b (отдельно, позже)** — масштабирование контента до требований ТЗ (2800+ заданий, 40+ тем). Не в объёме этого документа.

## 1. Источники и ограничение точности

Материалы по обоим инструментам — те же, что и в Этапе 1 (`Тип6_Матемашка/Матемашка_1.1.2.3_разбор.md`, `..._СПЕЦИФИКАЦИЯ_воспроизведения.md`, `разбор_img/*.png`, `help_chm/*`, `content/textures/2x/lab_chain*.xml`).

Пользователь запросил максимальную близость к оригиналу для обоих инструментов, но по факту изучения материалов это оказалось возможным только для одного:

- **«Два отрезка»** — механика полностью понятна по единственному скриншоту (`разбор_img/lab_otrezki.png`, `help_chm/.../3.5.png`): два измеримых отрезка с общей линейкой 0-30, текстовое условие сравнения длины, перетаскивание конца отрезка. **Реализуется близко к оригиналу.**
- **«Цепочка»** — в распакованных ресурсах есть только графика (`lab_chain.xml/png`: сегменты «верёвки», палитра из 4 категорий — фигуры/буквы/цифры/игрушки, кнопки переключения категорий, стрелки навигации) и один статичный скриншот. Правила самой закономерности и проверки ответа были зашиты в `.swf`, недоступном в распакованных ресурсах; живого экземпляра оригинала в этой сессии тоже нет. **Пользователь согласился снять требование точности для этого инструмента** — реализуется собственная механика с той же дидактической целью (продолжение закономерности) и тем же визуальным языком (верёвка + палитра категорий), без притязаний на копирование недоступной логики. Ассеты `lab_chain.png` — собственность вендора, не переиспользуются в любом случае (тот же запрет, что и в Этапе 1).

## 2. Точка входа: экран «Лаборатория»

Сейчас (Этап 1) кнопка на стартовом экране `MathMachineRuntime.tsx` называется «Лаборатория: Весы» и ведёт сразу в `WeightsTool` — потому что инструмент был единственный. С тремя инструментами нужен промежуточный экран-меню, как в оригинале (кнопка «Лаборатория» → список инструментов).

Новый компонент `packages/player/src/mathmachine/LabScreen.tsx`:
- Три кнопки — «Весы», «Цепочка», «Два отрезка» — открывают соответствующий инструмент.
- Кнопка «Назад» возвращает в стартовый экран `MathMachineRuntime`.
- Без данных/прогресса — чисто навигационный экран.

`MathMachineRuntime.tsx` меняет `screen === 'weights'` напрямую на переход через `screen === 'lab'` (рендерит `LabScreen`), который уже переключает на `'weights' | 'chain' | 'two_segments'`.

## 3. Модель данных

`packages/shared/src/mathmachine/model/schema.ts` — единственное изменение схемы:

```ts
// было:
export const MATH_TOOL_IDS = ['weights'] as const;
// станет:
export const MATH_TOOL_IDS = ['weights', 'chain', 'two_segments'] as const;
```

`MathToolSchema` (`{id, name}`) не меняется — место для новых id уже было зарезервировано комментарием ещё в Этапе 1. `MATHMACHINE_CONTENT_SCHEMA_VERSION` не меняется — структура контента не меняется, только допустимые значения `id`.

**Оба новых инструмента — без авторского контента**, как и Весы (это не задания темы/группы, а параметризуемые на лету упражнения — песочницы с генерируемыми случайными, но математически осмысленными параметрами, а не сохранённый в JSON контент). Это решение отвязывает Этап 2a от Этапа 2b: контент для лабораторий не нужно авторски готовить, они работают сами по себе на любом наборе валидных случайных параметров.

## 4. «Цепочка» — генерация и механика

Чистая логика (тестируется без DOM) — `packages/player/src/mathmachine/tools/chainLogic.ts`:

- **Категории элементов**: `'number' | 'shape' | 'letter' | 'toy'` — все 4, как в оригинале. Числа — реальные цифры (математический смысл); фигуры/буквы/игрушки — простая собственная векторная графика (не вендорский арт), для игрушек — минимальный набор simple-SVG-подобных иконок (например, мяч/кубик/шарик — той же сложности, что геометрические фигуры Этапа 1 в `TaskVisual.tsx`), не иллюстрации syntx.ai (те — предмет Этапа 2b).
- **Закономерность**:
  - для `'number'` — арифметическая прогрессия, случайный шаг ±1..±3 (не равный 0), случайное стартовое значение в разумном диапазоне (0-30, чтобы не выйти за пределы одного экрана и не задействовать отрицательные числа);
  - для `'shape' | 'letter' | 'toy'` — чередование двух элементов набора (АБАБ…) или трёх (АБВАБВ…), случайный выбор периода (2 или 3).
- **Длина цепочки**: 5-7 звеньев, случайно.
- **Пропуски**: 1-2 случайные позиции, не первая и не последняя (иначе закономерность не считывается однозначно).
- **Валидация**: точное совпадение категории+значения в каждой пропущенной позиции. Функция `checkChainAnswers(chain, placedAnswers)` возвращает per-slot результат (верно/неверно), как и остальной движок (не блокирует повторный ввод — при ошибке слот подсвечивается, попытка не ограничена, т.к. лаборатория не считает прогресс/ошибки в отличие от обычных заданий).

Рендер — `packages/player/src/mathmachine/tools/ChainTool.tsx` (react-konva):
- Горизонтальная «верёвка» — простая svg-дуга/линия (Konva `Line`), не вендорский арт.
- Заполненные звенья — элемент категории на «бусине»; пустые слоты — пунктирный кружок-плейсхолдер.
- Внизу — палитра: 4 вкладки-переключателя категории + строка элементов текущей категории (drag-source).
- Взаимодействие — полноценный drag-and-drop (Konva `Draggable`): элемент из палитры перетаскивается на пустой слот; попадание в пределах хит-зоны слота фиксирует элемент, мимо — возврат в палитру (тот же паттерн, что offset/pivot-исправление луча Весов в Этапе 1 — драг с чётким hit-testing, живая проверка на touch/мышь обязательна).
- Кнопка «Проверить» запускает валидацию, кнопка «Новая цепочка» — новую генерацию.

## 5. «Два отрезка» — генерация и механика

Чистая логика — `packages/player/src/mathmachine/tools/twoSegmentsLogic.ts`:

- **Параметры генерации**: длина опорного (первого, фиксированного) отрезка — случайное целое 4-20 см; направление отношения — `'longer' | 'shorter'`, случайно; разница N — случайное целое 1-10 см, с проверкой, что результат (опорная длина ± N) остаётся в пределах линейки 0-30 — если генерация вышла за границу, перегенерировать N в допустимом диапазоне (не менять шкалу линейки).
- **Условие** формулируется как готовый текст с уже подставленными значениями (не редактируемые поля): `«{Цвет1} отрезок на {N} см {длиннее|короче} {цвет2}.»` — те же два цвета, что в оригинале (розовый/зелёный), не настраиваются.
- **Проверка**: точное совпадение текущей длины второго (тянущегося) отрезка с целевым значением `опорная_длина ± N` (знак зависит от направления). Функция `checkSegmentAnswer(referenceLength, delta, direction, draggedLength): boolean`.

Рендер — `packages/player/src/mathmachine/tools/TwoSegmentsTool.tsx` (react-konva):
- Два горизонтальных «шнура» с общей линейкой 0-30 под каждым (тот же паттерн, что деления шкалы у Весов, только горизонтальная линейка, не чаши).
- Первый отрезок — статичная длина (не draggable). Второй — Konva `Draggable` по одной оси (X), с привязкой (snap) к целым см при отпускании.
- Кнопка «Проверить» запускает валидацию, кнопка «Новое задание» — новую генерацию.

## 6. Границы Этапа 2a (что НЕ входит)

- Авторский контент/арт для Этапа 2b (2800+ заданий, 40+ тем) — не создаётся здесь; оба новых инструмента работают на случайной генерации, без потребности в авторском контенте.
- Доступ к лабораториям из редактора (`editor-web`) — не меняется; лаборатории существуют только в исполняемом плеере, как и Весы сейчас.
- Изменения существующего Весов — не производятся.
- Изменения каталога/тем/групп/прогресса обычных заданий — не производятся.
- Дробный ввод ответа (FR-009, отложено ещё в Этапе 1) — не входит.

## 7. Тестирование и живая проверка

- Юнит-тесты на `chainLogic.ts`/`twoSegmentsLogic.ts` (без DOM, по прецеденту `weightsLogic.test.ts`): генерация всегда даёт валидные параметры (не выходит за границы линейки/диапазона чисел), проверка ответа корректна на пограничных случаях (ровно верное значение, ровно на 1 см мимо, оба направления отношения, оба периода чередования для нечисловых категорий).
- Живая проверка — тот же процесс (packaged Electron + CDP), что использовался в Этапе 1 для Весов/аудио. Задания лаборатории **не озвучиваются** (подтверждено разбором оригинала, `help_chm/3_3.html`: «кнопка озвучки … не активна») — риска класса C1 (аудио-бандлинг) здесь нет.
- Особое внимание при живой проверке — drag-and-drop hit-testing на обоих новых инструментах (прецедент Этапа 1: офсет/пивот-баг Весов был найден только живым прогоном, не тестами на чистой логике).
