## 0. Контекст и место в общем плане

Фаза 2 ТЗ (визуальный редактор для учителей) разбита на **две подфазы**
по решению пользователя (2026-09-11), т.к. совокупный объём (каталог +
Konva-редактор + роли + медиа-библиотека + пароли + экспорт) заметно
больше самой Фазы 1:

- **Фаза 2a (эта спека)** — ядро: каталог викторин, PIN режима учителя,
  Konva-редактор точек с полной формой вопроса, пароль конкретной
  викторины. Даёт полностью рабочий редактор (текстовые вопросы на
  готовом или собственном фоновом изображении, без картинок к отдельным
  вопросам/спецсимволов/экспорта).
- **Фаза 2b (отдельная будущая спека)** — расширения: библиотека медиа
  для картинок к вопросу/ответу/подсказке (FR-008/015), вставка
  спецсимволов (FR-014), экспорт в файл / обмен между проектами KIOSK
  (FR-013+018, переосмысление из Фазы 1 §1 действует и здесь).

Роль «Педагог (режим учителя, редактор викторин)» и обязательное
разграничение прав — ТЗ §3, дословно: «Разграничение прав должно
соответствовать роли: функции создания/редактирования контента и
административные операции не должны случайно изменяться пользователем,
работающим только в режиме обучения/просмотра.» Это требование целиком
относится к Фазе 2a (сам факт наличия защищённого режима учителя), не
делится между подфазами.

## 1. Навигация и экраны

`RusiqRuntime.tsx` получает новую ветку состояния параллельно игровому
потоку (интро→настройка→поле→результаты остаются без изменений):

```
IntroScreen (существующий, + новая кнопка «Режим учителя» в углу)
   ↓
TeacherGateScreen — ввод PIN; если PIN ещё не задан (первый вход) —
   форма «Задайте PIN режима учителя» вместо формы ввода
   ↓ (PIN верный)
QuizCatalogScreen — список викторин:
   - «Обучение грамоте» (встроенная, read-only, кнопка только «Дублировать»)
   - пользовательские викторины (кнопки «Редактировать» / «Дублировать» /
     «Удалить»; для защищённых паролем — «Редактировать» сначала
     запрашивает пароль)
   - кнопка «Создать новую»
   ↓ «Создать» / «Редактировать» / «Дублировать»
EditorScreen — Konva-канвас (фон + точки) + панель формы вопроса +
   кнопки «Сохранить» / «Отмена» / undo-redo / «Назад к каталогу»
```

Выход из режима учителя — кнопка «Выйти» на `QuizCatalogScreen` и
`EditorScreen`, возвращает на `IntroScreen`. Несохранённые изменения при
выходе из `EditorScreen` — подтверждение («Выйти без сохранения?»), по
той же логике, что и в редакторе Тип5.

## 2. Данные и хранение

### 2.1 Формат файла викторины

Переиспользуется существующая `RusiqQuizSchema` (Фаза 1,
`packages/player/src/rusiq/model/schema.ts`) без изменений полей — она
уже версионирована и уже содержит `passwordHash`. Меняется только ГДЕ
она хранится: в Фазе 1 единственный экземпляр был скомпилирован в код
(`content/rusiqContent.json`); в Фазе 2a пользовательские викторины —
данные, не код.

### 2.1.1 Начальное состояние новой викторины

`RusiqQuizSchema.image` — обязательное поле (не `nullable`), поэтому у
`EditorScreen` не может существовать промежуточного состояния
«викторина без фона» как валидного `RusiqQuiz`. Поэтому «Создать новую»
на `QuizCatalogScreen` — это маленький модальный шаг ДО открытия
`EditorScreen`, не часть самого канваса: форма из двух полей —
«Название викторины» и «Фоновое изображение» (`<input type="file">`,
локальный файл, читается через `Image()` в рендерере для получения
реальных `width`/`height` — та же дисциплина, что закрыла критичную
находку финального ревью Фазы 1: заявленные размеры ВСЕГДА берутся из
реального файла, не вписываются вручную). Только после заполнения ОБОИХ
полей открывается `EditorScreen` с уже полностью валидным `RusiqQuiz`:
`id` — новый UUID (`crypto.randomUUID()`, как и у проектов KIOSK),
`schemaVersion: RUSIQ_QUIZ_SCHEMA_VERSION`, `title` и `image` — из формы,
`intro: ''`, `themes: []`, `passwordHash: null`, `levels` — три уровня с
теми же подписями, что у встроенной викторины («Начинающий»/«Опытный»/
«Профессионал», id 1/2/3 — переименовываемые в настройках викторины),
`questions: []`, `genericDecoyPoints: []`. С этого момента объект ВСЕГДА
проходит `RusiqQuizSchema.safeParse` без исключений для промежуточных
состояний — черновик и есть валидная (хоть и пустая по вопросам) схема.

### 2.2 Хранилище на диске

По образцу `projectStore.js` Тип5 (один файл на сущность, не общий
массив): новая поддиректория `kiosk-rusiq/quizzes/<quizId>.json` в том
же каталоге пользовательских данных, где уже лежит история игр
(`electron/rusiq/ipc.js`, Фаза 1). Каталог строится чтением содержимого
директории при открытии `QuizCatalogScreen` — отдельного индекс-файла
нет (меньше состояний рассинхронизации).

Встроенная «Обучение грамоте» НЕ копируется на диск при обычной игре —
только когда учитель явно нажимает «Дублировать» на ней: тогда её
содержимое (полностью, включая все 608 вопросов) записывается как новый
файл с новым `id` и становится обычной пользовательской (редактируемой)
записью.

### 2.3 Новые IPC-каналы (`window.rusiqAPI`)

Дополняют существующие `load-user-data`/`save-user-data` (Фаза 1):

- `rusiq:list-quizzes` → `{ id, title, isBuiltIn: false, hasPassword: boolean, updatedAt: string }[]` — только пользовательские (встроенная добавляется на стороне рендерера, она не файл).
- `rusiq:load-quiz(id)` → полный `RusiqQuiz` или `null`, если файл битый/отсутствует (см. §5).
- `rusiq:save-quiz(quiz: RusiqQuiz)` → атомарная запись (tmp+rename, тот же паттерн, что уже есть у `save-user-data`), ПОСЛЕ `RusiqQuizSchema.safeParse` на стороне рендерера — главный процесс не валидирует повторно, доверяет уже провалидированному вызывающему коду того же приложения.
- `rusiq:delete-quiz(id)` → удаление файла.

### 2.4 Настройки режима учителя

Новое поле в схеме пользовательских данных виджета
(`RusiqUserDataSchema`, Фаза 1) — `teacherPinHash: string | null`
(default `null` = PIN ещё не задан). Хранится в ТОМ ЖЕ файле, что и
история игр (`load-user-data`/`save-user-data`), не в отдельном файле —
не нужно ещё одного набора IPC-каналов ради одного поля.

## 3. Модель безопасности

Два независимых уровня защиты — не путать один с другим:

1. **PIN режима учителя** — на уровне устройства/виджета в целом, хранится
   в `RusiqUserDataSchema.teacherPinHash`. Защищает вход в
   `QuizCatalogScreen`/`EditorScreen` от игрока/ученика (ТЗ §3). PIN —
   4-значный код (аналог уже принятого в продукте паттерна Тип8 для того
   же класса задачи — «режим учителя»).
2. **Пароль конкретной викторины** (`RusiqQuiz.passwordHash`, уже в схеме
   Фазы 1) — защищает ОДНУ викторину от правки даже другим человеком,
   уже прошедшим PIN устройства (сценарий: несколько педагогов на одном
   киоске, каждый не хочет, чтобы другой случайно поправил его викторину).
   Устанавливается/снимается из `EditorScreen` (поле «Пароль викторины»
   в настройках сохранения), необязательно.

Оба хэшируются одинаково — SHA-256 через `crypto.subtle.digest` (Web
Crypto API, доступен в renderer без дополнительных IPC-вызовов),
консистентно с уже существующим в проекте паттерном хэширования
(`licenseKeyHash` в `project.json`). Открытый текст PIN/пароля никогда
не пишется на диск и не хранится в памяти дольше одного сравнения.

## 4. Редактор точек (Konva)

Прямой порт паттерна Тип5 (`Workspace`/`WorkspaceBackground`/
`WorkspaceObject`/`WorkspaceTransformer`, `history.ts`), упрощённый:
объекты Тип5 — произвольные перемещаемые/трансформируемые/вращаемые
изображения; объекты РусIQ — точки фиксированного размера (как уже
рендерятся в `GameBoardScreen.tsx`), только перемещаемые, без вращения/
масштабирования/отражения (в игровом поле точки всегда одного размера и
формы — незачем и в редакторе).

Компоненты (`packages/player/src/rusiq/editor/`):

- `EditorScreen.tsx` — держит редактируемый `RusiqQuiz` в состоянии,
  собирает undo-историю, кнопки сохранения/отмены.
- `QuizCanvas.tsx` — Konva `Stage`/`Layer`: фон-изображение (по тому же
  принципу пропорционального контейнера, что уже есть в
  `GameBoardScreen.tsx`) + точки ВСЕХ вопросов викторины (не только
  текущего выбранного — учитель должен видеть, куда уже поставлены
  вопросы, чтобы не накладывать новые друг на друга) + их decoy-точки +
  общие decoy-точки поля; drag для перемещения, клик — выбор/открытие
  формы. Точки разных типов различаются цветом ТОЛЬКО в редакторе (не в
  игре — находка 6 финального ревью Фазы 1 запрещает различать их
  visуально в `GameBoardScreen.tsx`, но это ограничение не
  распространяется на инструмент автора, где учителю НУЖНО видеть, что
  он редактирует).
  Панель инструментов канваса — три режима добавления точки по клику на
  пустое место: «Добавить вопрос» (новая точка правильного ответа + сразу
  `PointEditForm`), «Добавить ложную точку к вопросу» (активен только
  когда выбран вопрос — добавляет в `decoyPoints` ЭТОГО вопроса), «Добавить
  общую ложную точку» (добавляет в `genericDecoyPoints` всей викторины,
  не привязанную ни к одному вопросу — реализует третью формулировку
  FR-012 «координаты точек без привязки к ним конкретного вопроса»,
  ≥10 штук по требованию ТЗ, счётчик уже добавленных отображается в
  панели, но НЕ блокирует сохранение при меньшем числе — жёсткая
  блокировка сохранения ради количественного порога создала бы риск
  потерять недооформленную, но иначе готовую викторину; вместо этого —
  предупреждение «добавлено N из рекомендуемых 10» ненавязчивым текстом).
- `PointEditForm.tsx` — форма вопроса: текст, ответ, тема (выбор из уже
  использованных тем викторины или ввод новой), уровень (1-3), вес
  (`price`), время на вопрос (`timeSeconds`), подсказка (`helpText`,
  необязательно). Для decoy-точки — только кнопка «Удалить эту точку».
- `useEditHistory.ts` — порт `history.ts` Тип5: `initHistory`/
  `pushHistory`/`undo`/`redo` на снимках `RusiqQuiz`.
- `QuizCatalogScreen.tsx`, `TeacherGateScreen.tsx` — экраны навигации
  из §1.

Пошаговое создание «с нуля» (FR-017) реализуется естественным порядком:
модальный шаг «название+фон» перед входом на канвас (§2.1.1, файл —
через `<input type="file">`, валидация по MIME/расширению, ТЗ §9), затем
на уже готовом канвасе клики добавляют точки одну за другой, каждая
сразу открывает форму вопроса — учитель физически не может пропустить
обязательные поля.

## 5. Обработка ошибок

- `rusiq:load-quiz` вернул `null` (файл битый/удалён между чтением
  каталога и открытием) — `QuizCatalogScreen` показывает сообщение и
  предлагает удалить битую запись, не крашится.
- `rusiq:list-quizzes` содержит файл, не прошедший `RusiqQuizSchema` —
  пропускается в списке (аналог `safeParse`-фильтрации, ТЗ §9 «некорректные
  пользовательские данные не должны приводить к аварийному завершению»).
- Ошибка `rusiq:save-quiz` (диск полон, нет прав) — видимое сообщение
  об ошибке, редактируемый `RusiqQuiz` остаётся в состоянии `EditorScreen`
  для повторной попытки, не сбрасывается.
- Неверный PIN/пароль — сообщение «Неверный код», без блокировки после
  N попыток (устройство физическое, не сетевое — нет смысла в rate-limit
  ради локального PIN у детского виджета).

## 6. Тестирование

- Юнит (без DOM): `rusiq/editor/quizStore.test.ts` — CRUD через
  IPC-заглушки (по образцу `ipc.test.js` Фазы 1); `useEditHistory.test.ts`

- Живая CDP-проверка (обязательна для UI, playbook §5): полный цикл —
  задать PIN → войти → создать викторину → выбрать фон → добавить точку
  → заполнить форму → сохранить → выйти → снова войти → правка сохранена
  на диске (читается реальный файл). Отдельно — сценарий пароля викторины
  (неверный пароль отклоняется, верный открывает на правку).
