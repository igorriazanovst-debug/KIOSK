# Тип 8 «Интерактивная таблица Менделеева» — дизайн

> Реализует требования строк 351–358 закупочной спецификации (ТЗ раздел 5,
> FR-002…FR-008 — полный текст в `ТЗ_08_Интерактивная_таблица_Менделеева.docx`,
> извлечён напрямую из XML документа, не по цитате). Аналог продукта «ОС3.
> Интерактивная таблица Менделеева Д.И. 1.7.1» (реестр РПО № 4133) — разбор
> оригинала: `Тип8_ТаблицаМенделеева/ТаблицаМенделеева_1.7.1_разбор.md`,
> `Тип8_ТаблицаМенделеева/ТаблицаМенделеева_1.7.1_СПЕЦИФИКАЦИЯ_воспроизведения.md`.
> Решения зафиксированы по итогам брейнсторминга 2026-09-10.

## 0. Контекст и место в общем плане

В отличие от Тип 6 «Матемашка» и Тип 7 «РусIQ», это **одна фаза, не
несколько**: буквальный текст ТЗ (раздел 5, FR-002…FR-008) не требует
визуального редактора контента — весь справочный контент (118 элементов)
встроен и неизменен, редактируемого пользователем контента в продукте нет
вообще (сверено с оригиналом ОС3 — там тоже нет редактора, только просмотр).
Роли «Ученик»/«Педагог» из раздела 3 ТЗ закрываются не отдельной системой
редактирования, а PIN-блокировкой одной вкладки внутри виджета (раздел 5
ниже) — решение пользователя, отличается от первоначального предположения
«роли уже разделены структурой Editor/Player KIOSK».

## 1. Источники и ограничение точности

Функциональные требования — из `ТЗ_08_Интерактивная_таблица_Менделеева.docx`
напрямую (unzip + `word/document.xml`, узлы `w:t`), не по пересказу — урок
ретроспективы Тип6 (там оценка объёма ТЗ трижды расходилась именно из-за
цитирования вместо сверки с оригиналом).

**Явно принятые решения, отклоняющиеся от прямого переноса референса ОС3**
(см. диалог брейнсторминга 2026-09-10):

1. **Данные элементов** — НЕ переносятся из разбора ОС3 дословно (в отличие
   от контента РусIQ). Числовые физико-химические характеристики (масса,
   tпл/tкип, электроотрицательность по Полингу, плотность и т.п.) берутся из
   открытых научных данных — они являются общеизвестными научными фактами,
   не объектом авторского права. Текстовые описательные поля (нахождение в
   природе, аллотропные модификации, тип кристаллической решётки, положение
   в электрохимическом ряду) переписываются своими словами по тем же
   открытым источникам, не копируются дословно ни из разбора ОС3, ни с
   zperiod.app. Разбор `Тип8_ТаблицаМенделеева/app_dump` используется только
   как ориентир состава полей/структуры карточки, не как источник текста.
2. **Фото образцов элементов** — **осознанно принятый юридический риск**
   (решение пользователя, тот же класс, что переиспользование текстов
   вопросов РусIQ): используются реальные изображения с zperiod.app (без
   водяных знаков/логотипов), не изображения из открыто лицензированных
   каталогов (Wikimedia Commons и т.п.). Лицензия на данные/изображения
   zperiod.app нигде явно не указана на сайте (проверено WebFetch
   2026-09-10) — закрытый коммерческий продукт. Если проект пойдёт в
   реальную поставку заказчику, рекомендуется юридическая проверка перед
   этим шагом — не блокирует разработку и тестирование (та же оговорка, что
   у РусIQ, раздел 1 п.3 дизайна РусIQ).
3. **PIN «режима учителя»** — не входит в буквальный текст ТЗ (ни в
   оригинале ОС3 такого нет), вводится как интерпретация раздела 3 ТЗ
   («разграничение прав должно соответствовать роли... функции... не должны
   случайно изменяться пользователем, работающим только в режиме
   обучения/просмотра») — согласованное переосмысление, задокументировать в
   трассировочной матрице как «реализовано через согласованное
   переосмысление», не «не реализовано» и не «реализовано буквально».
4. **Без стартового экрана** — оригинал ОС3 открывается на стартовом экране
   с логотипом ОС3 и переключателем 4 языков. По прямому указанию
   пользователя интерфейс только русскоязычный (без переключателя языка) и
   без брендинга ОС3 — стартовый экран не нужен, виджет открывается сразу на
   экране таблицы. Экономит объём работы, ничего не теряя функционально (ни
   одно FR не требует именно стартового экрана).

## 2. Границы фичи

**Входит:**
- Виджет `periodictable` — standalone-app полноэкранное Electron-приложение
  внутри KIOSK Player (по образцу `mathmachine`/`rusiq`).
- Формат данных 118 химических элементов (версионированная схема).
- Обе формы таблицы: короткопериодная (группы I–VIII, лантаноиды/актиноиды
  отдельными рядами) и длиннопериодная IUPAC (группы 1–18) — FR-004.
- Карточка элемента: сводная (по клику) + подробная («Подробнее») со всеми
  18 характеристиками FR-005.
- Классификации и подсветка FR-006: металлы/полуметаллы/неметаллы; s-/p-/d-/
  f-элементы; кислотный/основной/амфотерный характер оксидов и гидроксидов.
- Вкладки: Поиск (по названию/номеру/символу/массе) / Настройки вида (форма
  таблицы, цветовая индикация, подсветка групп — за PIN) / Легенда
  (расшифровка цветовой индикации).
- PIN «режима учителя», хранится в `widget.properties` проекта.
- Allow-list доступа к РЕДАКТИРОВАНИЮ проекта с этим виджетом
  (`mokretcov.m@poznaikino.ru`, тот же паттерн, что у Хронолайнера/
  Матемашки/РусIQ).
- Фото образцов элементов там, где физически существует образец (не все 118
  — сверхтяжёлые синтетические элементы без фото, честно показывается
  плейсхолдер/отсутствие поля, не выдумывается).

**НЕ входит:**
- Визуальный редактор контента — в ТЗ такого требования нет (в отличие от
  РусIQ FR-012/017), в оригинале ОС3 тоже нет.
- Переключатель языка интерфейса / названия элементов на 4 языках — по
  прямому указанию пользователя, только русский. Поля латинского названия
  (`_LatName`, часть FR-005) остаются — это отдельное обязательное поле
  карточки, не переключатель языка UI.
- Автообновление (FR-007) / бессрочная лицензия (FR-008) — уровень
  платформы KIOSK, не виджета (тот же вывод, что у РусIQ FR-025/026 и
  Матемашки/Тип5 для сравнимых платформенных пунктов).
- Стартовый экран с логотипом (раздел 1 п.4 выше).
- Экспорт/импорт, шаринг между проектами — не упомянуто ни в ТЗ, ни
  пользователем; не привносить по аналогии с РусIQ, там это была отдельная
  сознательная граница фазы под явное будущее требование обмена
  викторинами (FR-013/018), здесь такого требования нет вообще.

## 4. Формат данных элемента

Один JSON-файл на 118 элементов (`schemaVersion: 1` с первого дня — урок
playbook §2), не ZIP-контейнер:

```ts
interface PeriodicElement {
  schemaVersion: 1;
  atomicNumber: number;             // номер элемента (FR-005 п.2)
  symbol: string;                   // символ (FR-005 п.1)
  nameRu: string;                   // название на русском (FR-005 п.4)
  nameLatin: string;                // название на латыни (FR-005 п.5)
  atomicMass: number;               // относительная атомная масса (FR-005 п.3)

  // Позиция в таблице (нужна для обеих форм — раздел 7)
  period: number;                   // 1-7
  groupShortRoman: string | null;   // "I".."VIII" (короткопериодная форма); null для Ln/Act
  groupIupac: number | null;        // 1-18 (длиннопериодная форма); null для Ln/Act
  isLanthanide: boolean;
  isActinide: boolean;

  // Классификация FR-006
  electronType: 's' | 'p' | 'd' | 'f';
  elementClass: 'metal' | 'metalloid' | 'nonmetal';
  oxideCharacter: 'acidic' | 'basic' | 'amphoteric' | 'none';

  // Остальные 13 характеристик FR-005
  electronConfiguration: string;    // электронная конфигурация
  naturalOccurrence: string;        // нахождение в природе
  physicalStateNormal: string;      // агрегатное состояние при н.у.
  crystalLattice: string;           // тип кристаллической решётки простого вещества
  allotropes: string;               // аллотропные модификации (пусто, если нет)
  stableIsotopes: string;           // стабильные изотопы (пусто, если нет стабильных)
  electrochemicalSeriesPosition: string | null; // для металлов; null для неметаллов
  density: number | null;           // г/см³
  meltingPointK: number | null;
  boilingPointK: number | null;
  oxidationStates: string;          // характерные степени окисления
  electronegativityPauling: number | null;

  photo: { fileName: string } | null; // null — образца физически нет/не найден
}
```

Все 18 полей строки 355 ТЗ присутствуют (см. сопоставление с FR-005 в
комментариях выше). Позиционные/классификационные поля — служебные, нужны
для рендера обеих форм таблицы и подсветки, не входят в список 18, но были
и в оригинале ОС3 (`_GNum`/`_PNum`/`_Etype`/флаги классов).

## 5. PIN «режима учителя»

Блокирует ТОЛЬКО вкладку «Настройки вида» (форма таблицы / цветовая
индикация / подсветка групп) — ученик видит текущий выбранный учителем вид,
но не может его изменить без ввода PIN. Поиск, карточки элементов и Легенда
остаются свободны всем без исключения — справочная функция, защита не
нужна (осознанное решение, раздел 1 п.3).

Хранится в `widget.properties`, редактируется в Editor вместе с остальными
свойствами виджета (тот же allow-list, что на весь проект):

```ts
// packages/shared/src/periodictable/widgetProperties.ts
export const PERIODICTABLE_WIDGET_TYPE = 'periodictable' as const;

export interface PeriodicTableWidgetProperties {
  title?: string;
  teacherPin?: string;   // 4 цифры, по умолчанию '0000'; пусто = блокировка отключена
}

export const PERIODICTABLE_PROPS_VERSION = '1.0';
export const PERIODICTABLE_DEFAULT_PROPS: PeriodicTableWidgetProperties = {
  title: 'Таблица Менделеева',
  teacherPin: '0000',
};
export const PERIODICTABLE_DEFAULT_SIZE = { width: 1024, height: 768 };
```

UI-поведение: клик на «Настройки вида» без разблокировки → модалка ввода
4-значного PIN → при совпадении открывает вкладку на текущую сессию плеера
(не требует повторного ввода до перезапуска приложения — как активация
плеера, не как сессионный логин на каждое действие). Неверный PIN — понятная
ошибка, без блокировки/счётчика попыток (не банковское приложение, ТЗ
раздел 9 «Надёжность» требует не аварийно падать на некорректном вводе, не
более).

## 6. Экраны и навигация

```
Таблица (открывается сразу, форма — по последнему выбору учителя)
   │      клик по элементу → сводная карточка
   │            └── «Подробнее» → подробная карточка (все 18 характеристик + фото)
   └── нижние вкладки:
        • Поиск            — по названию/номеру/символу/массе, подсветка найденного элемента в таблице
        • Настройки вида   — ЗА PIN: форма таблицы (корот./IUPAC) · цветовая индикация · подсветка групп
        • Легенда          — расшифровка текущей цветовой индикации (без PIN)
```

## 7. Две формы таблицы

- **Короткопериодная**: группы I–VIII (римские), периоды 1–7, лантаноиды и
  актиноиды вынесены отдельными рядами под основной сеткой.
- **Длиннопериодная IUPAC**: группы 1–18 (арабские), 18-колоночная
  раскладка, лантаноиды/актиноиды либо в основной сетке на своих местах,
  либо тем же отдельным рядом — решить при реализации по рендер-удобству
  touch-экрана (оба варианта корректны с точки зрения IUPAC).

Обе формы рендерятся из ОДНОГО набора данных (раздел 4) — различается только
раскладка ячеек по `period`/`groupShortRoman`/`groupIupac`, не отдельные
наборы контента.

## 8. Классификации и подсветка (FR-006)

| Раздел вкладки «Настройки вида» | Опции |
|---|---|
| Цветовая индикация | Отсутствует · Классы элементов (металл/полуметалл/неметалл) · Электронный тип (s/p/d/f) · Характер оксидов и гидроксидов |
| Подсветка (обводка) | Металлы · Неметаллы · Металлоиды · s/p/d/f-элементы · кислотный/основной/амфотерный характер оксидов |

Данные для подсветки — поля `elementClass`/`electronType`/`oxideCharacter`
из раздела 4, не отдельная структура.

## 9. Хранение данных

В отличие от РусIQ/Матемашки, **пользовательских прогресс-данных нет** —
справочник без истории попыток/результатов, персистентности через IPC не
требуется. Единственное состояние, которое стоит сохранять между запусками
на конкретном устройстве, — последний выбранный учителем вид (форма
таблицы, индикация) — храним локально через `localStorage`/аналог в
рамках Electron-рендерера (не через `window.periodictableAPI`/IPC, это не
пользовательский контент, а UI-удобство, не требует атомарной записи).
PIN хранится не локально на устройстве, а в самом проекте (`widget.
properties`, раздел 5) — так его можно сменить централизованно через
Editor.

## 10. Контент: получение данных 118 элементов + фото

1. **Числовые/классификационные данные** — использовать существующий открыто
   лицензированный (MIT/CC0/public domain) датасет периодической таблицы как
   базу (принцип «сначала искать готовое», по правилу пользователя — GitHub/
   реестры пакетов перед написанием контента с нуля), сверить/дополнить по
   актуальным справочным данным IUPAC для недостающих полей (особенно
   характер оксидов/гидроксидов, положение в электрохимическом ряду,
   аллотропные модификации, нахождение в природе — эти поля в типовых
   открытых датасетах периодической таблицы часто отсутствуют и потребуют
   отдельного заполнения).
2. **Текстовые описательные поля**, которых нет в típичных открытых
   датасетах (нахождение в природе, аллотропные модификации, кристаллическая
   решётка, характер оксидов, положение в электрохимическом ряду) — написать
   по фактам из открытых научных источников, не копировать формулировки
   ОС3/zperiod.app.
3. **Фото образцов** — отдельный технический спайк ДО материализации
   контента: разобраться, как получить сами файлы изображений с zperiod.app
   (сайт закрытый, публичного API/экспорта нет по нашей проверке — см.
   раздел 1 п.2) — это не «скачать по прямой ссылке», а отдельная задача
   разведки (аналог разбора `app_dump` у ОС3, playbook §1 п.3: спайк на
   рискованное техническое решение ДО того, как закладывать в план). Если
   технически недостижимо в разумное время — эскалировать пользователю
   решение (оставить без фото / попробовать другой источник), не тратить
   часы на догадки.
4. Тест-инвариант материализации: подсчёт итоговых чисел (ровно 118
   элементов, все 18 полей FR-005 непустые кроме документированно опциональных
   — `allotropes`/`stableIsotopes`/`electrochemicalSeriesPosition` могут быть
   пустыми по факту химии элемента, не по недосмотру) — пишется вместе с
   конверсионным скриптом, не постфактум (playbook §12, тот же принцип, хоть
   тут и нет choice-контента/предсказуемости — есть риск «молча пропущенное
   поле»).

## 11. Тестирование

- **Чистая логика без DOM** (`packages/player/src/periodictable/*.test.ts`):
  валидация схемы данных (`safeParse`, тот же принцип, что
  `MathMachineUserDataSchema`/`RusiqQuiz` — недоверенные/сгенерированные
  данные всегда через одну функцию валидации), раскладка ячеек в обеих
  формах таблицы (полное покрытие 118 позиций без дыр/дублей), поиск по
  названию/номеру/символу/массе, PIN-проверка.
- **Живая CDP-проверка** (обязательна для UI, playbook §5): переключение
  форм таблицы, клик по элементу → карточка → «Подробнее», Поиск с
  подсветкой найденного, PIN-модалка (верный/неверный ввод), Легенда.
  Debug-хук `window.__periodictableDebug`, если `Page.captureScreenshot`
