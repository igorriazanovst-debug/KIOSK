# Программа и методика испытаний: виджет «БиоIQ» (Тип 10)

**Для кого.** Для приёмки. Каждый раздел ссылается на требования ТЗ, которые он закрывает; сквозная сверка — в `bioiq-acceptance-matrix.md`.

**Чем эта программа отличается от программы «ХимIQ».** «БиоIQ» — копия того же движка, поэтому разделы 1–7 повторяют её по составу. Но игровое поле у «БиоIQ» другое: не сетка ровных плиток, а биологическая схема, на которой области расставлены по живым структурам. Это открывает класс дефекта, которого у «ХимIQ» быть не могло, — **наложение кликабельных областей**. Ему отведён отдельный раздел 8.

---

## 0. Подготовка

1. Собрать плеер с проектом, содержащим один виджет `bioiq` на весь канвас.
2. **Очистить каталог данных** `%APPDATA%\kiosk-bioiq` — испытание должно начинаться с чистого состояния, иначе «первый вход в режим учителя» не воспроизвести.
3. Запустить плеер.

> Внимание: «БиоIQ», как «РусIQ» и «ХимIQ», хранит данные в профиле пользователя (`%APPDATA%`), а не в общем каталоге. Подмена `PROGRAMDATA`, которой изолируются стенды Типов 2, 3 и 4, на него **не действует** — чистить надо именно `%APPDATA%\kiosk-bioiq`.

## 1. Стартовый экран и справочные материалы (FR-021, FR-022, FR-023; строки 315–317)

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1.1 | Открыть виджет | Экран с названием предмета, описанием и перечнем тем встроенной викторины |
| 1.2 | «Справочные материалы» | Список тематических изображений; **их не меньше трёх** |
| 1.3 | Пересчитать изображения по темам | Каждая из трёх названных в ТЗ тем — **внутренние органы, растения, клетки** — представлена, и у каждой есть запас: не меньше двух изображений |
| 1.4 | Открыть каждое изображение по очереди | Картинка грузится (не пустая рамка), структуры **подписаны**, под ней пояснение |
| 1.5 | «Назад к списку», затем «Назад» | Возврат на стартовый экран без потери состояния |

**Отдельно проверить:** раздел открывается **без пароля**. Это учебный материал, а не инструмент редактирования; требование пароля здесь было бы ошибкой.

## 2. Партия: настройка и прохождение (FR-002, FR-006, FR-007, FR-008, FR-010, FR-020; строки 296, 300, 301, 302, 304, 314)

| № | Действие | Ожидаемый результат |
|---|---|---|
| 2.1 | «Играть!» → один игрок | Переход к вводу имени |
| 2.2 | Стереть имя, «Далее» | Дальше не пускает: партия без имени не начинается |
| 2.3 | Ввести имя, «Далее» | Выбор уровня: «Начинающий», «Опытный», «Профессионал» |
| 2.4 | Выбрать «Начинающий» | Выбор числа вопросов на игрока |
| 2.5 | Выбрать 5 | Игровое поле: вопрос сверху, изображение уровня, кликабельные области, таймер, текущая цена ответа |
| 2.6 | Ничего не нажимать до конца таймера | Засчитан неверный ответ, переход к следующему вопросу; таймер не зависает |
| 2.7 | Нажать заведомо неверную область | Подсветка красным, ответ неверный, ход переходит |
| 2.8 | Нажать верную область сразу | Подсветка зелёной галочкой, очков — полный вес вопроса |
| 2.9 | Нажать верную область под конец таймера | Очков заметно меньше, чем в 2.8 |
| 2.10 | «Сдаюсь» | Ноль за вопрос, переход дальше |
| 2.11 | «Показать подсказку» | Текст подсказки появляется по нажатию, до этого не виден. **Кнопка должна быть на КАЖДОМ вопросе** |
| 2.12 | Доиграть партию | Экран итогов: очки и доля верных по игрокам |
| 2.13 | «Подробнее» | Список вопрос-за-вопросом с пометкой и очками; «Назад к результатам» возвращает |
| 2.14 | Повторить партию на двух и на трёх игроках | Ходы строго по очереди, счёт у каждого свой |
| 2.15 | Пройти все три уровня | Наборы вопросов **не пересекаются**: вопрос, встреченный на первом уровне, на других не появляется |

**Отдельно проверить «Крупнее».** Нажать — изображение и области увеличиваются, появляется прокрутка, если поле не помещается. Нажать по увеличенной области — ответ засчитывается так же. Доиграть партию, начать новую — поле открывается **уже увеличенным**: выбор сохраняется между партиями.

**Отдельно проверить видимость поля.** На маленьком окне и на полноэкранном пройти все три уровня: **все области, включая верную, должны быть видны без обрезки**.

## 4. Редактор своих викторин (FR-013, FR-015, FR-016, FR-018; строки 307, 309, 310, 312)

| № | Действие | Ожидаемый результат |
|---|---|---|
| 4.1 | «Создать новую» | Пошаговый конструктор: название и изображение первого уровня |
| 4.2 | «Дублировать» встроенную викторину | Полная копия со всеми тремя изображениями и вопросами |
| 4.3 | Открыть копию в редакторе | Слева изображение с областями, справа свойства; вкладки трёх уровней |
| 4.4 | «Добавить вопрос», нажать на изображение | Появляется область; справа форма: текст, ответ, подсказка, вес, время, тема |
| 4.5 | Вставить спецсимволы в текст вопроса | Панель вставляет знаки: индексы (CO₂), заряды, ♀ ♂ ×, α β |
| 4.6 | Добавить картинку к вопросу, к ответу, к подсказке | Все три принимаются и показываются в игре |
| 4.7 | «Добавить общую ложную точку» | Счётчик под кнопками растёт |
| 4.8 | Посмотреть счётчик обманок | Написано, сколько сейчас и сколько **требуется по ТЗ** — не меньше десяти на уровень |
| 4.9 | Удалить обманки, чтобы осталось меньше десяти | Панель «Готовность викторины» называет уровень и точное число; **сохранение при этом НЕ запрещено** |
| 4.10 | Задать пароль викторины | Пароль требуется перед изменением этой викторины |
| 4.11 | Сохранить, выйти, перезапустить плеер | Викторина на месте со всеми правками |

**Почему 4.9 именно так.** Требования ТЗ описывают готовую викторину. Учитель, собирающий её с нуля, первые полчаса им не соответствует; запрет сохранения означал бы «не сохраняйся, пока не закончишь», то есть потерю работы. Проверка обязана **перечислить**, а не запретить.

## 6. Обмен викторинами (FR-014, FR-019; строки 308, 313)

**Готовый файл для проверки: `docs/bioiq-exchange-check.json`.** Его не нужно ниоткуда выгружать — импортируйте сразу и убедитесь, что в каталоге появилась викторина «Обмен — проверка FR-014» на 12 вопросов. Файл собран тем же кодом, которым экспортирует само приложение (`buildExportPayload`), и пересобирается командой:

```sh
cd packages/player
node --experimental-strip-types tools/bioiq/make-exchange-file.mjs
```

Проверено живьём 16.09.2026: импорт создал викторину в каталоге и восстановил на диске все три изображения-карты под новым идентификатором.

|---|---|---|

## 7. Устойчивость к повреждённым данным

| № | Действие | Ожидаемый результат |
|---|---|---|
| 7.1 | Испортить `userdata.json` (дописать мусор), запустить | Приложение **говорит, что файл повреждён**, и не показывает пустую историю как настоящую |
| 7.2 | Удалить `userdata.json`, запустить | Чистый старт, PIN спрашивается заново |
| 7.3 | Испортить файл одной викторины в `quizzes`, открыть каталог | Прочие викторины на месте, битая названа |
| 7.4 | Убрать права на запись в каталог данных | Сообщение о невозможности записи, а не молчаливая потеря |

**Почему 7.1 важен.** Молчаливый откат к пустой истории выглядит для учителя как потеря накопленной статистики, а не как поломка файла. У Типа 4 этот же класс дефекта однажды показал пустой список учеников вместо ошибки.

## 8. Геометрия игрового поля — раздел, которого нет у «ХимIQ»

У «ХимIQ» поле — сетка ровных плиток, области не налезают по построению. У «БиоIQ» поле — схема, области расставлены по структурам, и соседние легко перекрываются. Две наложенные области дают кнопку поверх кнопки: клик достаётся верхней, и верный ответ не засчитывается.

| № | Действие | Ожидаемый результат |
|---|---|---|
| 8.1 | Открыть встроенную викторину в редакторе, посмотреть «Готовность викторины» на всех трёх уровнях | Замечаний нет |
| 8.2 | В своей викторине положить две области внахлёст | Панель готовности называет **обе** области поимённо |
| 8.3 | Сдвинуть их впритык, край в край | Замечания нет: соприкосновение — обычный приём разметки |
| 8.4 | Создать два вопроса про одну и ту же структуру (одна и та же область) | Замечания нет: это разные вопросы об одном органе, поле схлопывает совпадающие координаты в одну плитку |
| 8.5 | На игровом поле пересчитать кликабельные области и сравнить с числом различимых на картинке | Совпадает: нарисованного, но не нажимаемого нет |

**8.4 — не придирка, а найденное поведение.** Проверка наложений сначала считала дефектом и полное совпадение областей, и на 120 вопросах встроенной викторины дала полсотни ложных замечаний. Совпадающие координаты движок схлопывает намеренно и следит, чтобы верный ответ победил в такой коллизии; опасно только **частичное** наложение.

## 9. Что этой программой НЕ проверяется

- **Windows 7 и 8** (FR-005) — плеер собран на Electron 39, эти системы не поддерживаются с версии 23.
- **Автообновление** (FR-024) — механизма нет на платформе KIOSK в целом.
- **Запуск экспортированного файла без установки продукта** (FR-019) — см. 6.5 и §4.2 матрицы.
- **Отдельная иллюстрация у каждого вопроса** (FR-009, FR-016) — механизм есть и проверяется в 4.6, но встроенная викторина им не пользуется; см. §4.1 матрицы.
- **Реестр российского ПО и бессрочная лицензия** — не код.
